# 数据完整性修复与验证记录

应用更新为 2.37.1（versionCode 75），数据库升级为 20。修复保全历史迁移中的子记录，将原图鉴归档纳入备份，并取消在线数据库文件覆盖恢复。旧版本 19 已经删除且没有备份的图鉴、早期升级已经丢失的付款，不能由这次修复凭空恢复。

## 数据迁移与备份行为

- `MigrationJsonLists` 使用 JSON 编码转换历史单颜色和单图字段，保留引号、换行与反斜线；仅修复损坏的历史颜色，不替换合法 JSON 中的转义。
- `MigrationDataGuard` 在重建服饰/价格父表时快照并恢复子记录，在外键开关两种情况下都保全价格、付款、穿搭关联和图鉴链接；套装重建还保全转换后的服饰行。保护位于原 Room 升级事务内。
- 修正 18→19 步骤，在删表前将两张图鉴表每行全部列（含原主键、关联和图片）保存到 `legacy_catalog_archive`。19→20 创建归档及恢复日志表；归档暂不恢复图鉴 UI，但可查询、JSON/ZIP 导出和重新导入。
- 格式 2 记录应用版本与数据库版本，导出包含 22 个本地业务/归档/共享库实体；恢复操作日志不属于用户备份内容。JSON 与 CSV 均使用数据库一致快照，CSV 补齐遗漏字段并增加归档/共享库内容。
- `BackupFormat` 明确迁移历史默认值、单图、颜色、分类组、时间戳、purchaseDate→付款；拒绝未来格式、未知字段/枚举、非法金额/主键/关联与损坏数组。导出前检查原始数据库列，不能将显示用转换器的空列表/枚举回退写成备份数据。
- ZIP 缺图时拒绝创建完整备份，格式 2 逐图 SHA256 校验，拒绝重复条目/无效路径；预览绑定输入内容哈希。操作由 Mutex 串行执行。HTTP 图片保留远程链接，不承诺离线保存远程图片内容。
- 恢复先在 images 下创建并同步独立 UUID 图片文件，再在一个 Room 事务中替换业务数据、逐字段检查全部表和外键。失败删除本次新增图片；旧图片目录始终保留，因此进程中断不会使旧库丢图。旧文件的额外占用是当前保留策略的代价，自动垃圾回收未引入。
- 日历和闹钟只在数据库成功提交后按 reminderSet 重建；`RestoreJournal` 随数据库提交，启动时重试未完成的外部清理。付款更新数据库失败时保留旧日历。图片删除检查本机真实 images 目录以及各实体/归档的持久引用，避免删除仍共享的文件。
- Android 29 及以上通过 MediaStore pending 状态发布完整文件，失败清理半成品；26～28 使用应用专用下载目录的 FileProvider 输出，避免调用不支持的 Downloads 接口。

## 已执行的验证

`./gradlew testDebugUnitTest connectedDebugAndroidTest assembleDebug` 在 Android 35 模拟器执行，7 项单元测试和 6 组仪器化测试通过；迁移组参数化覆盖 Schema 2～19→20 的 18 个起点。`python3 scripts/audit_data_integrity.py` 四项主机检查通过。另将 Git 暂存区导出到独立目录，排除其他未提交改动后重复上述构建与测试，全部通过。

| 测试 | 已核对的数据或故障 |
| --- | --- |
