# Lolita 产品与界面设计规范

生效日期：2026 年 10 月 18 日。

本规范用于新增功能及既有功能的产品、视觉、交互和数据改造。每次任务开始前必须阅读本规范和 [AGENTS.md](../AGENTS.md)，按功能涉及的范围执行，并在本次设计与验收记录中说明落实情况。

新增用户可见功能必须先以艺术家的角色和能力绘制界面图，再设计七套皮肤下的效果，最后实现并用真实页面对照验收。数据升级、图片展示、隐私和费用边界须在设计阶段一并解决。

## 适用范围与维护方式

- 本规范规定长期产品原则、共用设计流程与质量要求；AGENTS.md 维护架构、组件接口、构建、测试和发布的具体约定。二者共同执行。
- 用户最新明确要求优先。已授权的设计与实现连续推进，不因流程分步而额外设置逐步人工审批；用户要求先设计或暂不实现时，按其指定范围交付。
- 每项功能区分长期规则、当前采用的方案、待评审建议、实现状态与验证状态。历史助手建议、探索样片和未来规划不能直接当作已批准或已完成的能力。
- 具体模型型号、输入数量上限、数据库与备份版本、测试调用额度属于相应功能或发布的记录。实施前核对实际代码、schema 和最新决策，不把历史版本数值复制为永久要求。
- 长期规则变化时同步更新本规范与 AGENTS.md 入口；功能方案变化时修订该功能文档，标明取代的旧方案及影响。已经提交的任务和历史业务记录继续保留当时语义。
- 纯后台或纯数据变更按实际影响执行数据、隐私、生命周期和验收要求；没有用户界面时无需虚构页面。

## 产品目标与业务边界

Lolita 服务于日常个人衣橱管理：知道有什么、找得到位置、能够组成搭配、核对购买付款、记录实际穿着，并按需生成展示图或试衣图。裙装、配饰、假发、袜装、鞋履等应能在统一物品体系中使用。

功能设计需要说明入口、使用过程、保存结果、后续查看和退出方式。新增一个字段或按钮时，同时检查它对详情、编辑、搜索筛选、统计、提醒、备份和删除的影响，按实际依赖补齐流程。

不同业务概念保持清楚边界：

| 概念 | 回答的问题 | 设计约束 |
| --- | --- | --- |
| 物品品类与类型 | 它是什么 | 名称重命名不应悄悄改变类型语义或 AI 处理规则 |
| 商品父子关系 | 是否属于某件商品的配套小物 | 保留独立资料及共价或独立计价规则，不用来代替搭配关系 |
| 现有套装归属 | 物品属于哪个既有套装 | 变更归属须明确说明，不能为推荐或复用搭配静默移动物品 |
| 搭配用途 | 这次怎样一起穿戴 | 同一鞋袜、假发可以反复使用；需要可复用方案时另行设计引用关系 |
| 穿搭日记 | 哪天实际穿了什么 | 搭配计划、生成试衣图、准备清单勾选均不自动建立已穿记录 |
| 收纳位置 | 实际放在哪里 | 与订单、搭配和穿戴角色分别维护；未知位置保留未设置 |
| 购买与付款 | 买了什么、已付多少、还欠多少 | 遵守统一账本规则，引用次数和展示分组不产生重复消费 |

录入默认只呈现必要字段和少量常用项，详细规格与补充资料按需展开；折叠不清空已填值，并提供简短摘要。多个主操作在小屏大字下优先自然高度与通栏排布，不能挤成逐字换行。

新功能应减少第一次使用的负担。常见选项可直接选择，特殊值可就地新增并复用，详细规格按需后补。未知品牌、位置或价格应有清楚的未设置表达，不要求用户编造事实。具体必填项、品类层级和分期由该功能设计确定。

护理可用状态、准备清单、多对多搭配方案等扩展，须分别说明范围和数据关系；本规范不自动将这些规划纳入每次任务。

## 新增功能的设计与实施顺序

| 步骤 | 必须完成的工作 | 可审阅的产出 |
| --- | --- | --- |
| 查看现状 | 查看工作区状态、相关代码、现有组件、数据流及已确认设计；说明问题和影响范围 | 本次目标、使用场景、范围及现有约束 |
| 绘制界面图 | 以艺术家的角色和能力设计构图、留白、层次、图片、文字与主要操作，串起入口和关键页面 | 可直接查看的界面效果图及关键交互说明 |
| 设计皮肤效果 | 在同一业务流程上设计七套皮肤，覆盖浅暗模式，检查实际尺寸与主要状态 | 标注清楚的皮肤效果图或对照板 |
| 完成实施设计 | 明确数据结构和升级、备份、图片展示及引用、隐私、付费、失败恢复与验收方案 | 数据影响说明、图片规则和验收场景；无影响的项简述原因 |
| 实现功能 | 使用现有架构、组件、令牌和导航，按设计完成相关流程与兼容 | 应用实现、必要迁移和有针对性的回归 |
| 对照验收与交付 | 对照图稿检查真实页面、数据和行为，完成相应发布步骤 | 真实截图、验证记录、已知限制及交付结果 |

界面图必须在用户界面实现之前产出并归档。流程框图或低保真草图可辅助梳理，但最终图稿须能审阅实际排布、信息层级和视觉效果；文字说明、灰框或实现后的截图不能替代前置界面设计。

图稿按功能覆盖相关页面与关键状态，包括涉及的加载、空白、错误、选中、编辑、保存、待确认和成功结果。浅暗、小屏、大字体和键盘情境要能说明布局如何成立；不机械规定图稿张数，可使用有清楚标签和足够细节的对照板。

功能设计放入项目现有设计文档目录，图稿使用稳定路径归档，并由设计文档直接链接。概念图、交互原型和应用真实截图分别标注。实现偏离图稿时，核对原因并同步设计或实现，保留最终有效方案。

## 七套皮肤与视觉身份

七套皮肤统一操作习惯、信息层级和完成质量，同时保留整套可辨认的审美身份。页面、快捷入口、弹窗、图片画框、背景和图标均应融入当前皮肤。

| 皮肤 | 造型语言 |
| --- | --- |
| DEFAULT 甜美 | 饱满曲线、柔和层次与轻盈气质 |
| GOTHIC 哥特 | 尖拱、切角与清楚的结构张力 |
| CHINESE 中华 | 飞檐、交领与舒展笔势 |
| CLASSIC 古典 | 对称、克制与收束轮廓 |
| NAVY 海军 | 灯塔、舷窗及清楚的航海构件 |
| COUNTRY 田园 | 宽檐、围裙与自然柔和的轮廓 |
| VICTORIAN 维多利亚 | 拱形、层叠与精细画框层次 |

皮肤差异通过主体构件、轮廓、笔势及现有字体、材质、边框和留白体系表达，不能只换颜色、圆角、微小内纹或给同一符号加不同装饰框。图标个性覆盖导航、内容、操作、方向和状态；新增图标同步全部 provider，遵守 AGENTS.md 的绘制与回归要求。

加号、删除、保存、刷新、齿轮和箭头等保留直接语义。实际小尺寸下仍应可辨认，避免繁密装饰缩小主体；浅暗、不同尺寸、非方形区域和透明 tint 都需要成立。

背景与装饰保留主体留白，照片、金额、文字和操作清晰优先。新组件复用皮肤令牌及 LolitaCard、LolitaSection、SectionHeader、ImageFrame 等现有组件；新增令牌同步七工厂和暗色变体。

### 已认可的设计

以下为后续设计的默认边界，调整时须说明具体问题并提供对照；用户新的明确要求可更新这些选择。

- 首页保留搜索、四个主 Tab 及筛选、排序、视图控制的既定顶栏布局；扩展物品类型不直接堆成更多首页主 Tab 或底部导航。
- 付款年历的月份采用已认可的紧凑布局，不仅凭一般性的疏密偏好重排。
- 桌面标识沿用衣橱挂裙方向；五个已认可导航轮廓持续保留，其他图标同样维持各皮肤个性。
- 真实商标只使用已核验的官方图或头像及明确别名匹配。没有可信素材时保留文字回退，不生成仿标，不按相似名称套图。

## 页面布局与交互

照片应能清楚辨认，详情及时呈现名称与当前订单摘要；付款页面优先展示状态、订单金额、实付和余额。次级说明可展开，未知日期、未知余额、历史只读、超额及核对警示始终可见。

- 保持主要操作清楚、可达，避免重复保存入口和相互竞争的主按钮。卡片只保留一层必要内边距，避免装饰造成空白膨胀。
- 小屏、大字体、暗色和键盘打开属于必需设计情境。长名称、金额、鞋码及位置路径完整排布，必要时换行，不遮挡操作；正确消费 Scaffold、系统栏和 IME Insets。
- 品牌、类型等选项多时使用可搜索选择器。常用值与自定义值跨相关入口复用，添加候选不改写历史原值。
- 筛选、搜索和切换页面保留仍然有效的已选项；隐藏的选择可查看和移除。切换单件或批量编辑保留未完成输入与当前上下文。
- 新建、编辑和读取失败清楚区分。原记录未完成读取时不能当新记录保存；旋转、重入和进程恢复按既有草稿策略保留编辑内容。
- 保存过程防止重复提交，读取和保存期间禁用会破坏一致性的相关操作；保存成功、失败、退出和放弃草稿有明确结果。
- 正确提供中文文案、操作语义和可点击区域，检查相邻卡片的点击范围。加载态、图片失败及重试沿用项目共用组件，不伪造内容或截图占位。
- 动画、毛玻璃、粒子及滚动效果沿用现有皮肤体系；检查滚动惯性、取消、返回与资源清理，不能为装饰拖慢日常操作。

## 图片与素材展示

每个涉及图片的功能，在设计时列出实际展示位置，分别说明画幅、适配方式、裁切焦点、背景、画框、清晰度及查看方式。无需为不存在的使用场景新增页面。

| 实际场景 | 设计与验收要求 |
| --- | --- |
| 列表 网格 选择器缩略图 | 在真实小尺寸辨认主体；按用途选择 Fit 或 Crop，保持明确焦点，检查文字与选择标记遮挡 |
| 卡片封面 | 保持卡片规定比例；检查安全区、边缘裁切、圆角和皮肤画框，避免关键主体被截去后失去辨识 |
| 详情完整预览 | 可完整 Fit 查看商品，保持原图比例，高度受屏幕合理约束，并能进入放大查看 |
| 全屏查看 | 支持完整图和放大细节，检查长图、横竖图、切换和返回；不以缩略图冒充可辨细节的原图 |
| 编辑与裁切预览 | 明确原图、本次选区和实际输出；裁切副本与原图分开，不因预览改变原图或封面 |
| 装饰背景与收纳示意 | 可按既定设计 Crop，中央内容区保持可读；示意素材不表达用户实际拥有的库存 |

素材创作同时考虑缩略和完整展示。裙摆、长发发梢、刘海、鞋履及配套组件等关键内容要有合适留白和完整查看途径；不能只审阅大尺寸原图。细节密集的素材须检查缩小后是否仍可辨认。

图片验证覆盖透明底、浅暗背景、各皮肤边框、横竖图、长图、极端比例、加载和失败状态。真实横向商标完整 Fit，透明黑色商标保持可辨认的中性底色。

展示层裁切、按尺寸解码和缩略缓存不得覆盖源文件或拉伸原图。保留原始图片、顺序及来源；仅生成或追加新图不自动改变封面，设为封面需明确操作。新增缩略图字段或复制文件须有实际必要，避免无条件维护重复原图。

图片加载使用 LolitaShimmerImage 等既有组件，全屏缩放和编辑等特殊场景遵守其动画配置。存储、共享引用、取消清理、删除和备份统一走 ImageFileHelper 及现有引用保护，不能清理仍被业务、草稿、任务或备份使用的文件。

生成素材归档完整提示词、来源、版本及 SHA256；真实素材保存可核验来源。候选图须标明待定版状态，完成构图与实际用途验证后再作为正式内置资源。

## 导入与识图辅助登记

导入和识图服务于当前明确的商品、款式和字段。原始证据、文字提取、外观推断、用户确认值和未知值分别表达，并保留核对与纠正入口。

- 导入先预览和纠正，再保存；逐件与批量切换保留草稿。定金尾款身份可快速修正，合法配对相邻展示，变更配对后重新核对。
- 一个商品链接拆分多个物品时，按明确款式或类型逐件确认，完整详情随各件保留。不因普通颜色、尺码而展开，也不靠相似名称自动合并物品、品牌或位置。
- 品牌根据明确文字及已核验别名匹配；歧义让用户选择，不按画风猜品牌，不将通用参数或水印店名直接当成生产品牌。
- 参考报价、起价、区间价、定金、尾款和套餐总价分别表达。采用参考值只填写待确认金额，不自动建立实付或把套餐总价重复记到每件物品。
- 识图展示字段来源及对应文字或局部图片。外观建议不冒充官方名称或规格；无明文不推断鞋码、厘米、耐热温度、材质、实付或舒适度。
- 多款式、多颜色和多尺码信息先明确适用对象。尺码表保留行列关系，选择对应尺码后才能采纳该行数值，不能自动当作实际购入尺码。
- 选图、实际输入预览、费用确认与结果核对尽量在连续页面完成。实际输入须进入视区后再开放发送；整图超限应可直接框选，不能因尚未准备成功而隐藏唯一修正入口。识别结果逐项确认后填入编辑草稿，最终保存才写业务字段；不自动建品牌、分类、订单或付款。用户识别期间的手动修改、已有字段和冲突信息不得被陈旧结果覆盖。
- 未解析完详情、缺失图片或加载失败须清楚呈现，不能将空白或部分资料报告为完整导入。取消、重入和重试保持已保存结果，防重复创建并清理仅本次产生的无引用文件。

## 账本语义与资料核对

独立计价物品最多绑定一个当前有效订单，原有历史订单保留。订单金额包含已确认邮费；定金、尾款及其他阶段是付款计划，真实付款单独记录。修改价格、阶段或归属不得重写实付，删除计划不能使真实余额或未分配余额消失。购买证据随订单保存，归档、解绑、重绑或切换共价不能抹掉原证据。

完整账本采用付清即已拥有、未付清即待付款的项目规则。共用主件价格的小物继承主件判断，独立计价的小物按自身订单判断；有当前订单时不能用服饰编辑随意覆盖账本状态。

历史资料不足时，拥有证据、账本完整性和付款日期完整性分别处理。确认历史已购只确认购买证据，不生成付款，不表示资料全部补齐。启用付款跟踪须由用户明确确认真实付款已全部录入，计算余额与实际待付一致；未知实付日期仍单列待补，不因启用跟踪而消失。

- 无价格不表示免费或零元付清。历史资料未核对时，缺付款记录不能直接推断实付为零、欠款或逾期；正常完整账本按订单总额和已录真实实付计算余额，尚无付款时按未付处理。
- 未知付款日期保留未知，不用创建日、应付日或今天补造；未知日期实付计入有证据的总额，单列提示，不硬塞进某个年月。
- 未知阶段到期日可留空，不虚造当天到期、逾期或提醒。
- 历史金额、异常记录和合法自定义值完整保留，不能按金额相同自动去重，也不能为统计整齐改写原值。
- 当前订单实付、包含历史订单的全部已录实付、订单参考均价和待付余额分别命名并使用对应口径。按订单去重，共价小物、搭配引用和位置分组不重复收费。
- 金额计算沿用统一账本与整数分规则；显示保持准确的小数位，不能通过低精度动画改变真实显示值。
- 首页、详情、核对清单和统计共享资料核对来源，显示一致原因和单位。确认一个事实不提前隐藏其他待办；待办清零后入口实时隐藏。
- 状态、统计、提醒与日历随已提交账本变化一致刷新。历史已购和待核对资料不产生虚构尾款提醒，失败保留重试依据。

## 数据升级与备份兼容

设计阶段先列出受影响的实体、字段、枚举、设置、图片引用、任务请求和业务推导。基于当前实际 schema 制定迁移，说明旧值如何保留、新值如何初始化及不确定值如何表达。

1. 数据库结构变化时递增版本、实现并注册 Migration、导出 Room schema，核对外键与唯一约束。没有结构变化时不为流程形式强行升数据库版本。
2. 保全原始 ID、日期、金额、图片顺序、父子关系、套装、穿搭、订单、实付与应保留的用户设置。允许变化限于事先列明并验证的派生状态、设备图片路径、系统日历指针及安全引用重置；本机设置与业务备份范围分别声明。无法可靠证明的分类或历史状态留待确认，不按模糊名称静默推断。
3. 历史衍生状态确需刷新时采用可重复执行或有一次性标记的方案，避免启动反复改写。用户删掉、改名或移除图片的默认内容不自行恢复。
4. 新实体或字段同步完整备份 JSON、ZIP、预览数量、恢复校验及适用 CSV。旧备份缺失新增字段时显式迁移；未知格式版本、业务字段、非法枚举或损坏数据按现有严格校验处理，不静默丢弃或错型回退。
5. 草稿、来源证据、个人模特照片、必要任务输入、待确认结果与其他持久图片引用按其业务纳入完整备份和路径重映射；密钥始终排除。完整 ZIP 包含本地引用图片字节，JSON 只保存图片引用，CSV 只承担适用的可读字段且不支持全量恢复；缺少必需引用图片时不能报告完整无损备份或恢复成功。
6. 恢复先验证和暂存，在事务与既有协调屏障中提交；失败不覆盖旧库或误删原图片。备份、任务取消、图片删除和恢复并发时遵守统一锁序与引用保护。
7. 旧任务和历史记录使用原请求版本与语义读取。恢复的活动任务保留证据并转中断，不启动付费重发；资源缺失明确受阻，不静默改用当前默认图片或模板。
8. 按受影响范围验证旧包同签名覆盖升级、旧备份导入、新备份往返和失败保护。以独立基准逐字段、关联、设置和图片 SHA256 核对，数量一致或成功打开文件不足以证明无损。

数据库、备份和任务协议的当前版本以实际代码及导出 schema 为准，历史设计文档中的版本数值仅适用于其记录的阶段。

## AI 功能与质量要求

### 服务选择与输入确认

选型先核对用户实际可用的账号、网络、付款方式、接口能力和同类样本效果。商品资料识图不采用 OpenAI；识图与生图分别评估、配置和说明，不将识图约束扩大为删除现有生图服务选择。

服务、模型、模板和额度在具体功能设计中记录。提交前展示本次用途、实际输入、服务及可能计费；切换服务、图片、模式、人物或模板后，陈旧确认失效。选择、预览和裁切本身不自动调用识图或生图。

任务提交时固定请求与实际输入快照。排队后改变默认人物、头模、名称或分类不能修改旧任务的付费内容；缺少旧资源或校验失败时明确阻止执行，不静默替换。

### 商品与人物保真

商品图优先保留柄图、蕾丝、袖长、裙长、腰线、卷度、鞋型、组件数量和叠穿遮挡，避免为美化而重新设计商品。不补造不可见背面或配件，不因只见单只就补成一双，也不为展示袜鞋缩短裙摆。

裙装正面人台、普通小物独立展示、全头假发戴所选头模等模式按品类分别设计；发片不能自动变成整顶假发。头模候选须逐款检查长短发、构图留白与小尺寸效果后定版，空白头模生成成功不足以证明佩戴效果。

个人照片模特尽量保留面容与体型，不自动瘦身或拉长腿；仅参数方式使用虚拟人脸，不夹带隐藏照片。试衣使用已确认人物底图，保持其身份、体型和姿态；明确选择假发时允许按该物品替换头发。

生成图是视觉辅助，不提供厘米级身体还原、合身预测、尺码准确或不可见细节可靠还原的承诺。保留原图和生成来源，AI 生成图不能作为真实规格的明文证据。

当前试衣的物品输入上限及至少一件基础服装等门槛按现行协议执行。搭配记录容量与 AI 本次输入容量分开，超限时由用户明确选子集，不静默截取或移除选择，不用拼图绕开限制；历史只记录本次实际发送的物品与角色。

### 结果保存与后台任务

展示图和个人模特先待确认，明确保存后成为业务资料；追加图片不自动设为封面。完整试衣沿用其成功后写入独立历史的规则，不能把所有结果强行套成同一种保存方式。

生成提交后可以离页、切底栏、锁屏，并通过任务中心查看。任务不依附页面生命周期，展示真实阶段和排队情况，不伪造进度百分比；离页和旋转不自动放弃已接受的任务或待确认预览。

系统终止、关机或进程丢失后保留记录及必要输入，按实际状态中断或恢复已持久化结果，不承诺无条件继续远端请求。失败、中断及取消不自动发起新的付费请求；主动重新发起需重新检查输入并确认。取消本地等待不承诺服务端停止计费。

删除任务与删除业务结果分别处理。保存、舍弃、取消、恢复和重复点击应保持幂等，不能丢失已确认资料或误删共享图片。

### 费用与效果评估

真实付费测试按本轮明确授权的调用数或费用范围执行并记录消耗，不沿用旧任务剩余额度。正常预览、切换皮肤或重启不消耗新请求。

代码测试验证规则与流程，真实接口验证接入，商品和人物样本人工评审验证视觉质量。提示词、受控接口、样片和模拟器各自只证明其覆盖的范围；没有真人或目标设备证据时，不宣称人物相似度、合身或设备故障已经解决。

## 隐私与资料出口

- 按当前操作仅发送必要内容。局部识图只上传最终选区像素，不附带整图、框外内容、EXIF 或相册路径；展示实际上传预览，保留原图。
- 个人模特切到仅参数方式时不上传先前选过的照片。使用已保存模特试衣时仅使用当前确认底图和物品参考，不再次夹带原始自拍、身体参数或私密备注。
- API Key 使用现有本机加密存储，不回填，不进入 Room、任务、Intent、SavedState、日志、备份、源码或 APK。发布凭据存于仓库外授权位置，不在报告中打印。
- 分享按用户本次选择提供图片、名称及可选品牌，默认排除金额、备注、渠道、位置和个人规格。金额隐私设置实时覆盖所有相关页面与新增摘要。
- 私人照片和资料可随用户主动完整备份保存；隐私要求不等于从备份遗漏业务照片。新增同步、共享或对外服务时明确公开字段，保留既有本机私有字段。
- 网页导入沿用用户主动提取与现有访问边界，不采集 Cookie 或引入无必要的高权限桥接。权限按操作实际所需申请，拒绝或取消有明确可继续路径。

## 验证与交付标准

验证以实际改动和风险选择，运行必要的构建与回归，不为形式添加与实现相同的测试。应用代码变更至少通过项目规定的 Debug 构建；正式包按 AGENTS.md 执行 clean Release 构建与签名检查。

| 验收方面 | 必须核对的结果 |
| --- | --- |
| 视觉 | 实际页面与图稿对应，七皮肤浅暗、实际尺寸、图片裁切和关键状态成立 |
| 操作 | 小屏、大字、键盘、搜索筛选、保存退出、返回重建和错误恢复可用 |
| 业务联动 | 相关列表、详情、编辑、统计、核对、提醒使用一致语义，既有记录不被意外改变 |
| 数据 | 受影响迁移、旧备份、新备份往返、图片引用、失败和并发保护有证据 |
| AI | 受控验证与真实付费结果分别记录，输入、次数、服务与人工质量结论可核对 |
| 升级与发布 | 正式签名可覆盖升级，版本、源码、附件和校验一致，用户正常更新路径得到检查 |

设备验证使用独立 AVD、测试数据库与独立设置，不卸载或清理用户设备来绕过签名、迁移或测试问题。USB 脚本只证明其实际执行范围，不能替代数据无损或图片恢复验证。

应用代码任务默认完成本次提交、推送及 GitHub 与 Gitee 正式发布，让用户通过正常更新和覆盖安装测试；纯文档任务核对差异后提交推送，无需升应用版本、重建 APK 或创建 Release。用户明确指定的范围优先。

远端源码、发布附件和应用更新入口分别核对。发布页存在、附件可下载与应用检查更新成功分别记录；遇真实失败如实说明，不能只以本地构建或推送宣称全部交付完成。具体签名、分发渠道、更新探测与凭据规则遵循 AGENTS.md。

7. 验收场景、相应构建和测试、真实截图与必要的人工质量评审。

- [ ] 已说明并验证相关数据迁移、旧备份兼容、图片引用和失败保护；无影响项有理由。
- [ ] 已核对账本、统计、核对入口、提醒和其他相关流程的一致性。
