# 服饰、小物与付款管理实现记录

版本为 2.38.0（76），Room schema 21，完整备份格式 3。设计与验收场景见 [改造方案](plans/2026-10-11-item-pricing-redesign.md)。

## 实现范围

- 一件独立计价服饰最多绑定一个当前订单；商品金额与邮费共同组成应付总额。全款、定金尾款、多段付款使用同一账本，阶段计划与实际付款分开保存。
- 改价或调整阶段不重建历史实付；删除阶段只解除可选阶段关联，不减少债务。余额按订单应付减实际已付计算，付清变为已拥有，撤销付款后重新回到待付款。
- 主件与小物支持一层关系。共用价格的小物继承主件状态且不重复计价；独立计价的小物按自己的账目判断。禁止循环、多层挂载及删除仍有小物的主件。
- 历史多价格、零金额或异常金额保留原记录并等待核对。旧未付行保留为原始计划；没有购买证据的愿望单预算不自动记成实付。未知实际付款日期保留未知，不用创建日期或应付日期代填月统计。
- JSON、图片 ZIP、预览及 CSV 覆盖订单绑定、付款阶段、邮费、实付关联和小物关系。提醒与日历在事务提交后处理，通过恢复日志重试；未知到期日不创建提醒。
- 淘宝导入按数量拆分并以整数分分配订单实付和邮费，保留订单来源；分配结果与实付日期需用户确认。不能自动把名字相似的商品吞并为小物。

历史存储金额仍使用 Double，以便原样保存；新输入限制两位小数，账目计算和比较使用整数分。退款、取消和未知邮费独立状态尚未建模。

## 验证方法

最终构建命令：`./gradlew clean assembleDebug testDebugUnitTest connectedDebugAndroidTest`。

| 测试类 | 关键验证 |
| --- | --- |
| BackupFormatTest | v1/v2 到格式 3、旧日期缺失、历史多价格、异常原值、小物关系、字段完整性和拒绝未来格式 |
| StageAccountingTest | 部分付款、未指定阶段的实付顺序抵扣、阶段与订单分离、整数分精度、历史计划超额时限制整体债务 |
| ImportAccountingTest | 数量拆分、邮费与实付分配、只选部分商品时不重复分摊 |
| DataIntegrityTest | 2–20 各版到 21、外键关联保全、历史预算语义、JSON/ZIP 恢复、图片 SHA256、错误回滚 |
| OrderBusinessTest | 唯一价格、改价保留定金、邮费多段、删除阶段保留债务、实际日期统计、共享与独立小物、父件删除限制、重复恢复到非空数据库 |

模拟器为 Android 15 / API 35。页面检查覆盖主件搜索与返回、唯一价格入口、1000 元商品加 20 元邮费、300/720 两段计划、300 元实付后 720 元余额、到期日待定及独立实付日期。截图已检查，关键字段没有裁切。USB 实机和七套皮肤全量视觉检查未执行；提醒唤醒与真实系统日历的权限组合仍需实机验证。

最终清理构建成功：29 个单元测试（备份 17、阶段计算 7、淘宝分配 5）及 20 个 Android 设备测试全部通过，无失败或错误。设备用例包含 2–20 版共 19 条数据库升级链到 schema 21。编译仍有原有 Compose 绘图 API 弃用等警告。

历史计划超额时，阶段提醒、日历及逾期合计受订单真实余额限制；原始计划不被裁剪。金额超范围或精度超过两位的历史记录保持原值并等待核对，不能绑定为当前订单。

调试安装包：`app/build/outputs/apk/debug/app-debug.apk`。发布须从已提交源码执行 clean assembleRelease，并验证签名、版本号与上传文件校验和。
