# 裙子正面人台图实验：实现与验证（2026-10-15）

## 结果与入口

2.49.0 / 107 新增裙子详情“生成人台图（实验）”。适用有图片的 CLOTHING 裙类：JSK、OP、SK 和固定中文裙类；愿望、待付款、已拥有均支持。选择一张已有参考图、填写可选的200字内补充说明，生成后先完整预览并可放大，明确点击“添加到裙子图片”才追加到原图库末尾。原图和主图顺序不变。只做正面，不做三视图。

没有新增实体、字段或备份格式：Room27 / 备份7 保持。已保存人台图作为普通 Item 图片参与现有 JSON、ZIP、CSV、恢复与删除流程；待保存预览不属于业务备份，也不插入试衣历史。

## 新样本探索与接受标准

使用 imagegen 默认内置工具，三件新裙子共四次调用；完整提示词、输入ZIP条目、SHA256、时间、图片及失败原因见 [来源记录](mannequin-front-evaluation-2026-10-15.json)。应用固定提示词与该记录的通用提示词一致，不依赖逐件人工描绘领口和花纹。

| 数据 | 结果 | 处理 |
|---|---|---|
| 虞美人OP，大花印花/长袖/同图正背 | 取正面，长袖、浅色领片、主印花与裙长辨识清楚；花纹、褶皱、腰结重绘 | 可供人工预览 |
| 昆虫记OP，真人/头饰/手臂/黑色泡袖 | 移除真人与头饰，保留泡袖、衣身和层叠裙体；小印花重绘 | 可供人工预览 |
| 古董蛋糕OP，复杂花边/独立手袖 | 初次仍混入原图注明不包含的独立手袖 | 不可直接保存，保留失败证据 |
| 同一古董蛋糕，加排除手袖说明 | 独立手袖移除，保留裙子袖端蕾丝；心形与花边细节仍重绘 | 可供人工预览，支持可选说明 |
| 玻璃窗SP，局部/侧向/混合头饰 | 仅检查，未生成 | 不用它证明缺失结构 |

接受范围是有人工核对的 AI 展示效果图，不是商品结构或尺寸的精确复刻。原图始终保留，结果先预览、显式追加；没有因样片好看自动写入用户服饰。

## 请求、密钥与所有权

沿用现有官方 Images edits 传输：固定HTTPS endpoint、型号 `gpt-image-2.5-sunburst`、medium、1024×1536、n=1、PNG。官方文档提供该模型多图编辑接口，参见 [OpenAI 图像生成文档](https://developers.openai.com/api/docs/guides/image-generation)。请求含固定空白模板与所选原图两张，不自动上传全部图库。

试衣和人台共用一个 API 实例与 `ImageGenerationGate.process`，跨入口防重复付费；无自动重试。生成前和图片解码后再次核对最新Item、Category和参考图归属。Key继续使用现有 Android Keystore 加密/noBackup 存储，共用遮罩配置对话框，不回填、不进入业务库/日志/备份/SavedState。取消等待不能保证服务端不计费。

预览经 ImageFileHelper 完整PNG校验与UUID落盘；返回交付前取消也清理未引用文件。恢复时验证Item身份、精确自有绝对路径、完整尾块、尺寸和解码；不接管、删除无效或已属于图库的路径。保存持有独立任务，UI等待取消或VM销毁不得在提交前删除图片。原子追加在真实Room事务中读取最新行，只更新图片/修改时间，重复同一路径幂等；记录删除后拒绝保存。删除服饰在同一事务中采集最新图片集合，避免旧快照漏掉新图片。

## 页面与导航

独立 Screen.Mannequin / MannequinViewModel，不污染服饰编辑草稿。沿用七皮肤卡片、分区、顶栏、Fit图片、全屏查看器和滚动注册；复用现有图标，没有新增IconKey。

生成、恢复、待处理预览、保存和离开状态均阻止底栏/快捷意图跳走。恢复未完成时顶栏和系统返回均拦截；有效预览必须确认放弃。保存或取消返回先离开原entry，再消费排队快捷穿搭；pop按原entry身份保护。
