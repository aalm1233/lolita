# 2.78.3 原生退出诊断增强

用户提供的 2.78.2 日志显示本应用主进程 reason=5/status=6，退出与导出相隔约15秒；Java 未捕获异常和备份普通异常均无记录。依据 Android 官方定义，确认这条记录是原生 SIGABRT。尚不能确定出错组件、触发入口或与历史数据的关系，也不能据导出时的 Java 堆统计认定崩溃时内存不足。PSS/RSS 为0表示没有有效采样，不能解释为没有占内存。

## 最终实现

现有「个人 → 导出诊断记录」保持原布局、皮肤及主动系统保存流程。仅报告内容扩展为 `lolita.diagnostics.v2`，最近Java/备份错误文件仍兼容。最近主进程退出和最近原生退出分别标注时间；原生退出的应用版本未知，不将升级前的崩溃归属当前版本。

`NativeExitTrace` 按官方 tombstone protobuf 编号解析，最多4MiB输入、十万字段、512线程条目，只提取崩溃线程最多64帧，单节不超过32KiB。输入保持内存中的有界缓冲，未保存原始文件；未知/内存/日志/错误文本字段不解码。只输出架构与信号数字、合法代码文件基名、代码符号、相对PC/函数偏移及十六进制Build ID。无系统记录、API不支持、读取或结构失败、超过上限分别明确标记。读取只在用户主动导出时执行，沿原IO协程；不在启动读取，不增加依赖/权限/网络上传。

Room34、45实体、备份16、衣橱/心愿/图片/草稿/服务地址均无变更。原生捕获不装信号处理器，不干预系统终止过程。无界面变化，不补绘未改界面或重复七皮肤截图；前置后台/隐私范围见[设计](plans/2026-11-08-native-crash-diagnostics.md)。

## 定向验证

- 14项JVM通过：原7项Java记录回归和新增7项原生解析。覆盖AOSP形状、字段及map乱序、只保留崩溃线程、私人标记过滤、帧/输入/输出上限、非法长度/wire/varint、异常输入流、过量线程/字段和proto3默认值。
- Debug构建与androidTest构建通过；3项正常设备方法通过：既有真实resolver导出及失败保留、真实个人菜单系统选择器取消、显式探针之后的真实系统原生栈读取及resolver导出。菜单用例此次按AVD原窗口运行，不宣称重复小屏/大字视觉矩阵。
- 显式测试专用SIGABRT使隔离测试进程实际退出（宿主预期 `Process crashed`），重新启动从系统历史取得reason5/status6、signal6及4个调用帧，报告无完整私有路径。SIGABRT探针只在androidTest且显式参数启用；不在正式应用提供人为崩溃入口。
- 不重复未受影响的39项历史迁移子场景或私人全库/原图审计；此前审计及限制仍见[逐版本核查](square-all-upgrade-paths-2026-11-07.md)。

## 实际设备后续

本版是诊断增强，尚未修复反馈手机的两个退出。用户覆盖安装后先导出TXT，可读取系统仍保留的旧原生记录；若提示unavailable/无历史或缺栈，需要再复现一次后重开导出。系统环形缓冲、OEM限制或超上限可能仍无法提供调用位置。模拟器探针仅证明采集/过滤/导出链路，不冒充小米原始故障复现。
