# 表格订单导入交互复查（2026-10-14）

范围：本轮默认逐件填写、批量筛选、付款类型修改、配对操作和确认提示。对已有实现做独立代码复核，并用真实 Compose 测试复现边界。

## 已复现并修复

1. 未完成的金额草稿丢失：分摊邮费输入 `12..`，下一件再上一件时显示 `NaN`。原始文本仅存于卡片的 `remember`，离开卡片后由 Double 重建。现将商品金额、邮费、实付和手动尾款的原始文本保存在 `ImportItemState` 中；数值仍单独校验，非法输入不能导入。模式切换、逐件导航均保留草稿。
2. 逐件订单汇总错误：同一订单选中三件时只显示当前一件的份额，并写成“本次选择 1/3”。现始终按本次全部选中资料汇总当前源订单；批量筛选仅显示可见商品所属订单，汇总仍覆盖该订单全部选中资料。
3. 配对改变后核对状态陈旧：解除配对或修正另一条付款类型后，旧关联商品仍标记已核对，可能沿用之前手动尾款直接导入。现解除、更换或付款类型改变均取消所有受影响资料的核对；重复点击相同类型、原配对保持不变。ViewModel 拒绝同一商品自配或相同付款类型互配。
4. 小屏大字体底部布局：320dp、两倍字体、100 条已完善资料时，进度挤占导入按钮，文字高度超过 200dp；下一件也被挤成多行。现进度位于通栏导入按钮上方，窄屏大字体下导航进度另起一行，上一件和下一件均分宽度。进度改用“条资料”，避免与配对合并后的服饰件数混淆。
