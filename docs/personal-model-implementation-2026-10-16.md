# 我的模特实现与验证（2.53.0）

## 使用流程

个人 → 我的模特 → 捏一个我的模特。照片方式至少脸部照或正面全身照一张，可另加侧面照；仅用参数方式生成虚拟面容。身高、体重必填；围度、肩宽、内侧腿长和描述可选。所选照片复制到本机持久草稿，参数方式不发送此前隐藏的本人照。

每次生成需要主动确认服务和上传内容，沿用本机加密 Key 与后台串行图像任务。预览先留在任务中心，确认保存后才进入人物库。以此调整会另存新人物。试衣只上传已保存底图与服饰，排队后改默认、改名或删除人物不会改变本次底图。

图片为1024×1536单张中性背景全身照；照片优先身份，尺寸作为生成约束，不自动瘦身或拉腿。真人相似度、精确体型和同人换装保真仍需真实输入与另外授权的调用额度评估，本轮没有付费API调用。内置模板和测试色块只用于流程验证。

## 数据与边界

- Room28→29新增`personal_models`、`personal_model_drafts`，试衣历史和任务追加可空人物快照；历史不设级联人物外键。草稿存原始字符串，统一引用数组持有UUID图片路径。
- 严格v2任务区分人物原照与服饰；旧v1仍严格三个字段。确认保存是单个Room事务并幂等。待确认、失败、中断、取消的个人生成保留输入；主动重试重新核对，绝不自动付费重发。
- 个人试衣入队在同一事务核对确认时id/底图路径，防止完整恢复复用Long id后误用另一个人；入队后保留实际图引用。默认id是本机偏好，完整替换恢复成功后清空；失败保留。
- 备份9同步JSON、ZIP、CSV、预览与恢复；旧1–8补空。ZIP基于完整源路径生成确定性UUID归档名，避免同名异图混合。恢复活动任务只转中断，保留必要原照，不启动云请求。
- 个人参考图完整读取预算80MiB/36MP/单边16384；JPEG/PNG额外检查压缩流，拒绝截断主图＋伪EOI。主JPEG完整后允许Motion Photo/UltraHDR容器尾部，只验证主静态图，不宣称验证附加视频/HDR。API26/27个人照片限JPEG/PNG，28+其他格式用ImageDecoder；原服饰读取规则不变。

## 实施决定

- 用户批准设计后直接实施，无第二次计划确认；使用隔离工作区，保留原目录已有未跟踪文件。并行工作只分派互不重叠的源码，导航由主任务合并；Gradle/设备命令串行，避免已观察到的缓存冲突。
- 新增独立草稿表以建立可枚举的持久图片归属，成本是迁移和备份多一张表。名称在UI/仓库去空白，领域边界拒绝未规范化名称，统一60字。
- 完整恢复后清空默认人物，而非只检查id存在，以免Long id复用误指另一人；代价是恢复后需重新选择一次。
- 不沿用此前复杂服饰的付费试验预算，本轮真实相似度保持未验证。
- 独立封面功能先占用2.52.0/111，合并保留该改动，本次版本顺延2.53.0/112。
