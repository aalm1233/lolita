# 虚拟试衣的穿戴关系与补充描述

## 目标与现状

多件物品需要共同形成一次穿戴：裙撑支撑裙摆、外搭包容内层、帽饰压住或遮挡头发、高跟鞋改变足踝与承重姿态，不能按选图顺序粘贴。用户可说明 BNT 前后位置、系带、掖入与叠穿方式。现有 TryOnRequest 只有笼统遮挡提示，试衣 UI 没有说明字段；ImageTaskRequest 已有 200 字 instructions 和完整 promptSnapshot。

## 实现前界面设计

绘制时间在 UI 实现之前。采用现有 LolitaSection：已选物品后、生成前确认前放置“穿戴要求（选填）”，多行文本、示例、200 字计数和简短物理穿戴说明。底部唯一生成按钮保留，随 IME 上移。付费弹窗列出本次物品与完整要求，可滚动；修改要求使旧确认失效。历史与任务详情显示该次要求，便于核对与重试。

- [七皮肤浅暗设计图](../visuals/2026-10-19-tryon-physics/design.svg)：颜色与边框沿既有皮肤，文字自然换行。图片沿原 Fit/放大实现，不生成新模板或改动参考图。
- 320dp/2 倍字采用通栏文本框，内容滚动；键盘仅压缩工作区，保留生成操作。

## 数据与执行

- 复用任务 instructions（200 字）与 v4 请求结构，新增试衣提示词修订号 2；旧修订号 1 的已提交提示词原样执行，不重写历史。Room30/备份10无结构变化。
- 描述进 SavedState，重试只回填一次，用户编辑/清空后重建不恢复旧内容。提交复制描述；队列、历史 requestSnapshotJson 和完整备份沿现有 JSON 保护该描述。无新增图片或密钥字段。
- 新提示词先要求分析实际物品结构、空间和接触，再统一生成。按角色追加相关约束，不要求展示全部遮挡物，不凭图片顺序决定前后。自定义要求作为穿戴偏好，不允许改人物身份、变造商品或执行物品名称里的指令。
- 已选择鞋履时，足踝随真实鞋楦/跟高调整，可进行必要局部承重姿态调整；保留骨骼长度、身份与体型。无鞋则保留底图鞋。无裙撑则不凭空添加支撑体积，紧身裙不强行撑成钟形。
- 现有服饰、账本、位置与穿搭关系不写入；结果仍独立保存。现有选图/缩略图/完整放大、失败保护及共享图片引用保持。

## 隐私、费用与验收

界面说明补充要求会发送到所选服务，付费确认展示全文；密钥仍仅本机加密。不会额外调用模型分析、不自动重试。真实付费按本轮明确额度执行，未授权不调用。代码只能验证规则与请求，不能保证生成器的物理准确性。

定向覆盖领域提示词（角色交互、输入顺序、鞋/裙撑条件、描述边界）、v4旧新提示词快照、真实队列执行与历史/备份描述、VM重试/清空/陈旧确认、真实Compose七皮肤浅暗/小屏/大字/键盘。发布 clean Release 并同签名覆盖升级；仅核对受影响旧任务快照，不重复无关全库/图片审计。

## 实现与验证记录

已实现角色条件化穿戴提示词与选填200字描述，复用v4快照修订2，现代页面即使清空描述也冻结该次提示词；无语义的旧调用继续走旧协议。旧v4任务直接使用原promptSnapshot，无请求JSON批量重写。已补任务详情与历史显示，重试只初始化一次，输入修改后陈旧确认拒绝。

本轮未获得新的付费调用额度，真实API调用0次；未验证裙撑/多层/BNT前后/高跟鞋生成视觉质量，不宣称真实物理或合身准确。
