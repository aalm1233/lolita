# 淘宝链接的颜色与尺码组合选择

## 目标和现状

用户确认按「黑色 S、白色 M」等具体组合勾选，每个组合保存一件，同色可选多码。当前颜色候选只提供款式身份，批次继承商品参数尺码，紧凑恢复也未保存逐件尺码。本轮接通网页SKU规格→预览组合→逐件草稿→已有Item.size，不改已保存物品。

## 实施顺序和范围

1. 先归档可审阅前置图及七皮肤浅暗、小屏大字状态，再实现。
2. 解析公开SKU的尺码／鞋码等明确尺寸维度，组合包含其余明确规格；SKU有完整路径清单时只提供清单中的组合，无路径清单时按公开选项生成待核对组合，不声称有货。保留商家规格原文及稳定维度身份，不猜尺码、不从尺码表自动选值。
3. 有尺码候选时新增默认关闭的「按颜色和尺码分别导入」；初始不全选。开启后按颜色／款式分组，用可换行尺码芯片多选，可搜索规格，隐藏已选不丢失，显示实际选择件数。没有尺寸候选时沿用已有颜色选择；关闭新模式仍是原单件／明确部件拆分。
4. 每个选中组合独立报价、独立importToken，保存明确尺寸到Item.size，名称带完整规格原文。报价仅精确完整规格对应，不把同色其他尺码、套餐价或起价批量下放。保留默认心愿、每件完整独立图片副本、逐件保存／暂停／幂等。
5. 紧凑SavedState保留逐件尺码、组合身份和报价；旧草稿缺字段继续原行为、旧队列仍继承原共享尺码。最多选30件，过多组合明确提示而不静默截断；大量候选提供搜索。

Room30／备份10及Item.size既有备份、CSV、历史尺寸选项机制均不变；只增加导入会话元数据，不迁移、重写原记录或创建付款。图片显示、完整Fit／放大、下载与清理沿用现有组件和引用保护；不新增图片、权限、Cookie采集或AI调用。
