# 穿戴结构证据与局部约束研究

用户在2.60.1发布后要求继续按“可见结构／未知参数分开，再约束穿戴与外观”的路线试验，并沿用本轮100次额度。开始时已用17次、余83次；不合并上一轮16次余量。用户不知道目标腰封的封高、适用腰围和软硬参数，按未知处理。

## 证据与范围

原备份中目标灰黑腰封只有一张正面偏侧商品图，能辨认中央两枚主扣、扣座、两侧系带、链条与侧后褶皱结构，没有可信厘米或背面闭合资料。另一个同名物品是不同配色，不能当作同一件的另一个角度，也不混进本次输入。

本阶段先在私有评估目录比较真实请求，得到足够证据再决定应用改造。没有新增页面或控件；UI图稿、七皮肤验收及数据协议改造在实际采纳时按受影响范围执行。本阶段不因生成成功而自动采用，不向用户补填推测尺寸，也不把合成图当作规格证据。

## 比较顺序

1. 冻结现行提示词的局部合成对照，以及明确前幅占比、两枚扣具与侧片后绕的文字约束。
2. 依[官方交互编辑指南](https://docs.volcengine.com/docs/ark/seedream-5-0-pro-editing-guide?lang=en)，比较整件框选、前幅与侧片分别定位、仅修正侧片。归一化图像坐标只表示像素区域，不是厘米或刚性几何约束。
3. 对照腰部近景与侧前方诊断画幅，观察细节和曲面的可读性；不同视角不能算原正面全身效果通过。
4. 先建立无装饰灰色接触曲面，再转移商品外观；灰色占位是形态假设，需要继续核对原轮廓，不能作为已知物理参数。
5. 保持提示词和输入不变，仅提高输出分辨率，观察全身图中的小扣具与接触细节。该API变体留在私有实验代码，不能称为正式应用请求。

另用一次builtin image_gen对照同样的两输入局部任务，只比较服务响应，不据此切换应用服务。各次请求先入持久账本，无自动重试。主机JPEG归一化不是Android原生编码验证；builtin样片也不是应用OpenAI API联调结果。

## 采纳条件

同一方法重复后，腰封前幅、侧边后绕、衣料受力、扣具数量与形状、链条挂点及人物／主裙保全须同时成立。灰模、近景或一张看起来较好的照片不能单独证明整条流程稳定。若多步方案有稳定改善，再设计可审阅的中间结果、明确的每步计费和冻结请求；不将研究过程藏进现有一次确认后。

商品原图和衍生试穿图只留私有评估目录，公开资料仅记录方法、次数、摘要及限制。

## 本阶段结果

本次新增15次：14次Seedream、1次builtin image_gen；累计32/100次，余68次。所有请求已有终态，没有自动重试。这里的请求成功只表示生成返回，不能当作穿戴质量通过。逐次提示词、输入和输出摘要见[对照记录](../tryon-evidence-study-2026-10-20.json)，完整图像及提示词保存在本机私有评估目录。

| 对照 | 实际观察 | 采纳 |
| --- | --- | --- |
| 局部对照、前幅占比文字 | 两枚主扣大致可辨，前幅和侧片仍有平板感，细节会重画 | 未采纳 |
| 整件框选、部位分别定位、仅修侧片 | 区域定位不等于固定曲面或刚性扣具；侧翼仍外张 | 未采纳 |
| 原生产提示词加穿戴说明 | 一次生成的局部曲率有变化，没有守住稳定贴合与细节 | 未采纳 |
| builtin image_gen模型对照 | 侧接触较柔和，但两枚主扣变成三枚，人物和裙子也重画 | 未采纳 |
| 腰部近景、侧前方诊断 | 扣具更清楚，曲面更易观察，侧部外翘仍在；不代表原正面全身通过 | 未采纳 |
| 灰色占位→外观转移／几何辅助图 | 自由灰模会新造下摆；受原图约束的灰模加入外观后，又恢复平板和侧翼，未锁住原曲面 | 未采纳 |
| 1536×2304输出对照 | 比1024×1536有更多细节像素，未解决侧片闭合与接触，仍有细节改绘 | 未采纳 |

这批结果不支持“只补尺寸或增加一次分析生成，就能稳定解决腰封贴片感”。可见的两枚主扣会被改写，已经足以说明未知参数之外还有外观与曲面约束未被守住；不能将失败全部归因于用户不知道尺寸。

灰模、坐标和高分辨率的效果也不足以证明可靠三维约束。后续若继续这条路线，应优先验证能固定可见几何与原外观的表示或编辑方式，再比较真实多角度／尺寸证据的帮助；继续堆同类提示词没有得到本阶段的正面支持。

本阶段保留2.60.1的原生成流程、图片输入和一次明确确认，不接入未达标的多次付费研究步骤。应用源码、UI、请求快照、Room30和备份10均无变化；未重复构建、设备回归或创建新Release。只核对并提交本次研究文档，真实付费对照不冒充设备／历史任务兼容测试。
