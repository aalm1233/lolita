## 改进优先级

| 优先级 | 发现与建议 | 预期结果及验收方式 |
| --- | --- | --- |
| P1 | **个人页遵守金额隐私开关。** `SettingsScreen.kt` 中 ProfileSection 未接收 showTotalPrice，当前订单实付无条件渲染；格式还把金额限制为零位小数 | 关闭后整行和无障碍文字消失，无占位；开启后保留两位小数，长金额可换行。零位小数问题来自代码检查，本轮没有带小数实付样本的运行验证 |
| P1 | **降低文字区域背后的装饰权重。** 中华实拍中花枝、云形粒子穿过空态标题和说明附近，强描边又让普通卡片都像重点 | 保留皮肤背景和动画体系，先调整现有背景 alpha 与正文表面的遮蔽关系；普通卡边框低于主动作的视觉强度。分别审浅暗，不统一去掉所有皮肤边框 |
| P1 | **空态提供就地动作。** 衣橱「添加第一件物品」，穿搭「记录一次穿搭」；导入／恢复作次级入口 | 用户看到解释就能行动。该空态隐藏重复 FAB，有数据时恢复原 FAB；筛选无结果使用「清除筛选」，不能误报衣橱为空 |
| P1 | **试衣先完成搭配选择。** 压缩人物区，将完整小预览、人物名称和更换操作并排；选物品紧随其后；服务收成可展开摘要 | 普通字号首屏同时看见人物和选物品入口。继续支持完整放大、8 件上限和基础服装校验；不为紧凑裁掉人物脚部或物品主体 |
| P2 | **实验室按目的呈现。** 展示图与虚拟试衣采用同等层级的图文入口；图示明确标「效果示意」；我的模特、头模、识图归到紧凑工具组 | 更容易理解两种功能的结果。保持全部原路由；服务配置状态提前可见，但「已配置」只代表本机有配置，不代表网络或额度已验证 |
| P2 | **减少普通管理行的视觉竞争。** 个人页保留已对齐的实验室入口，仅试验普通卡边框及表面层级 | 不再次改大实验室标题；保留16/24sp和阅读字体。图标、箭头、文字轴线维持现有约定 |
| P2 | **小屏大字单独检查底部安全区。** 320dp、两倍字实拍中底栏文字已非常接近手势区域 | 实施时测量文字完整边界与点击范围；保持系统字号，用导航区域自然增高和正确 Insets 解决，不压缩字号 |
| 保留 | 详情 Fit 主图、订单优先、统计四项概况及完整八类、现有搜索与选择保留规则 | 这些是现有优势。统计顺序、年历紧凑月份、主导航和今日穿搭位置不重排 |

以上属于本轮设计判断，不是用户访谈结论；没有测得完成时间、点击率或留存变化，不承诺量化提升。

## 三张主页面的落地规格

### 空衣橱与穿搭空态

保留首页单行搜索、四 Tab、筛选／排序／视图控制。空衣橱以插画、短标题、主按钮组成一个连续区域；插画是装饰示意，不代表用户库存。常规尺寸插画高度建议不超过约220dp，小屏／大字体减到约96–128dp；整个内容可滚动，不把按钮强行锚在屏幕中间。图稿里的大插画表现艺术方向，实际高度依此约束。

「添加第一件物品」进入现有编辑页，不降低必填和保存校验。「从淘宝导入」先让用户明确选择商品链接或订单文件，再进入既有入口，不暗中选择导入方式。恢复备份继续进入现有恢复页，替换后果和缺图警示保留。「记录一次穿搭」进入现有穿搭编辑；这里没有复用首页专属的今日穿搭卡。

### 实验室

图像示例选取无私人信息的专用素材，区别输入与预期用途；不能冒充真实服务测试结果或承诺保真。服务状态从现有配置仓库投影，识图和生图分别展示；主稿只画图像服务行，识图的状态保留在其入口说明。进入配置并返回后保留原导航位置。

已有全局活动任务栏继续优先显示真实任务，不在实验室再复制一张大进度卡。工具区必须保留任务中心和 API 配置的明确可达入口，不能为了图片把全部功能挤进不可发现的更多菜单。

### 虚拟试衣

三个阶段表达人物、物品、核对，不新增三套路由；允许回到前项调整。已选图可查看和移除，切换筛选不清空隐藏选择。物品、人物、服务或穿戴要求变化后旧费用确认失效。

有配置时主按钮「核对输入与费用」先打开实际上传确认，确认后才提交。未配置时按钮仍为「配置服务密钥」，不能显示可生成。费用确认展示实际人物底图、每件参考图、穿戴资料、所选服务、请求数和可能计费；本例3件物品对应4张输入只是示例。取消等待仍可能计费、失败不自动重发等规则保持。

## 状态与适配

| 情境 | 设计行为 |
| --- | --- |
| 加载 | 沿用与最终布局匹配的骨架；未知配置先显示检查中，不闪成未配置 |
| 真空态／筛选空态 | 前者提供创建，后者提供清除筛选；异常读取提供重试，不当作空库 |
| 已选／超限 | 数量和隐藏选择可见；超限明确选子集，不静默丢弃 |
| 输入或服务失效 | 就地说明并提供修正，保留已有选择，禁用提交 |
| 发送／后台／待确认 | 使用真实任务阶段；后台执行和结果核对保持，不伪造百分比 |
| 小屏与两倍字 | 卡片自然增高，双列改单列，示例图缩小；字体不缩小补救，次级工具允许滚动 |
| 键盘 | 服务及可选说明收起后仍可展开；唯一主按钮位于正确消费 Insets 后的 IME 上方；费用关键信息不能随帮助隐藏 |
| 金额隐藏 | 个人、统计及相关金额摘要同步移除，仍保留物品数量和非金额入口 |

本轮已看过现有小屏暗色页面，尚未运行新设计的键盘、无障碍、状态恢复与触控回归；上表是实施验收要求。

## 数据、图片与隐私边界

本轮只增加文档与设计图片，无 Room、备份、CSV、原图或用户设置的产品变更。后续若按本稿只改展示与路由入口，预计无需迁移；实施时重新核对，不能把「预计」当作迁移检查结果。

继续使用 Entity → DAO → Repository → StateFlow ViewModel → Composable；配置状态只读投影，任务和账本仍走原业务层。涉及组件为 SkinEmptyState、LaboratoryScreen、TryOnScreen、SettingsScreen 与现有皮肤令牌。共用改造后扩展对应回归范围。

缩略图使用 LolitaShimmerImage，商品与人物选择预览以 Fit 为主；装饰／示意封面可 Crop 但保留关键主体，点击业务图片能完整放大。实际编辑／全屏禁用圆形揭示动画，保留原文件、顺序和引用保护。

未上传私人照片、密钥、数据库或商品图到设计生成服务。设计稿由文字描述生成，修订只使用本轮生成图。应用内识图、生图、试衣调用为0；内置 image_gen 的设计绘图与应用接口测试分别记录，不据此评价应用AI质量。备份和删除边界保持原规范。
