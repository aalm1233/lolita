# 广场内网服务与增量浏览

状态：实施中。用户已确定持续采集入 SQLite、API 只读、App 进入及下拉刷新、原图按需加载；本轮内网验证后仍按项目约定发布正式版本，花生壳另行接入。

## 范围与流程

本机 Codex 调度 dsh 采集，主助手只读落地资料并核验；统一本地入库命令接收已核验公开资料，写独立服务 SQLite。API 不调用采集器、不接收 SQL、不开放发布或文件浏览接口。此次使用既有六店已验收资料验证入库，提供后续定时任务可调用的入口；不新建未指定时间和店铺范围的调度。

服务与 App 私人 Room 分离。服务保留店铺、商品完整规格、动态、图片索引和递增变更记录。每个动态及其关联商品以短事务提交，互不相关的动态可逐项可见，不要求整批发布。相同标识按记录 revision 判断更新，相同版本不同内容拒绝；不因缺席删除。SQLite WAL；写入与 API 在同一机器，写任务串行去重。

API：健康检查、店铺、动态分页、商品详情、按游标的变更，以及图片缩略/原图。仅明确路由，外部只读。响应不含服务器路径、原始证据、账号或个人资料。变更记录保存当时完整关联资料，使翻页游标不会跳过并发修改；重试不会重复登记。服务数据库身份变化时重建游标并合并本地资料，不清空衣橱。

## 先行界面设计

艺术图稿在应用实现之前生成：[关键状态](../visuals/2026-11-06-square-lan/artist/main.svg)、[七皮肤浅暗](../visuals/2026-11-06-square-lan/artist/skins.svg)。保持现有标准顶栏、两列商品画廊、搜索/类别/店铺/筛选与详情完整 Fit。顶栏添加低频「广场服务」配置，默认留空，支持填写内网 HTTP 或 HTTPS 服务地址，清空即停止请求；后续可直接填花生壳 HTTPS。服务设置仅本机保存，个人备份不新增地址。

下拉刷新在动态页和无缓存空态可用，指示器不遮挡主操作；只由用户下拉显示刷新指示，自动查询在后台进行。地址配置复用标准 AlertDialog、皮肤输入/按钮，320dp 两倍字、IME 下可滚动。已有缓存遇连接失败不出现错误页、Snackbar、Toast、弹窗或通知；无缓存保持「暂无店铺资料」与本地导入操作，不能把网络失败表述为全局不可用。

## 图片、数据与生命周期

目录在本地独立缓存；网络目录允许尚未下载的图片，旧 ZIP 导入仍全量校验。列表读取缩略，详情完整图按需获取并校验 SHA 后保存；缩略不冒充私人原图。只有首次加入心愿/准备草稿需要复制的完整原图才预下载，沿用原 UUID、事务、引用保护、备份16，不传私人资料、不写账本。已收藏图片与服务彻底独立。

App 前台进入异步检查更新；广场下拉再检查。短超时、合并并发刷新；网络不占衣橱锁，不阻塞启动导航。取消正常传播，网络/协议/图片失败写本机类别日志，不暴露内部路径或凭据。SQLite 写入、接口游标及本机目录提交均应可恢复；未验证响应不推进游标或覆盖缓存。

Room34、45实体、备份16不变。公开目录缓存不进入私人备份，原 ZIP 离线恢复入口保留。无 AI 上传和付费调用；既有采集角色约定不变。本轮不操作花生壳、不开放公网。
