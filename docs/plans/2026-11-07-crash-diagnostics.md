# MIX Flip 2 两处退出：本机诊断

用户确认 2.78.1 后广场服务入口仍退出，设备为小米 MIX Flip 2；追加确认 JSON 导出中途也是应用直接退出。此前历史目录 null 修复不能视为这个现场的修复。

## 范围与证据

广场入口同步只设置地址和弹窗状态；其 ViewModel 另有衣橱、广场来源和草稿的异步订阅。JSON 导出先读取并校验完整数据库快照，再 Gson 序列化和发布下载文件。普通 Exception 会转换为页内提示；直接退出还需区分未捕获异常、OOM、系统杀进程和原生错误。暂没有该设备异常栈，不认定两处同因，不改变数据校验、不清缓存或私人资料、不猜测升级依赖。

先补可导出的本机证据，再针对实际异常修复。记录 Java 未捕获异常的类型与代码位置；错误消息、SQL、商品名、地址、账号、图片、请求、路径、线程名均不记录。保存当时应用版本、设备型号、Android API、Java 堆统计；API 30+ 导出时读取本包最近一次历史退出原因和内存统计，不读取系统 trace。普通备份导出失败也记录相同脱敏栈，便于区分被捕获失败。最多保留最近一次崩溃和最近一次导出失败，各 32 KiB，放 noBackupFilesDir，自动云备份与衣橱备份均不包含。

## 前置界面设计

复用个人页原 SettingsMenuItem，在检查更新后放「导出诊断记录」，说明「设备、异常位置与内存状态；不含衣橱内容」。图标复用七皮肤现有 FileOpen provider，卡片、留白、字重和箭头沿用同级菜单。不新增弹窗或页面，不改地址弹窗，减少对故障入口的依赖。点击由系统文件选择器选择保存位置；取消不写入，不自动上传；保存失败保持原记录并给出重试提示。此入口无需先成功导出衣橱。

前置艺术排布、七皮肤浅暗和 320dp 大字构图在 [artist](../visuals/2026-11-07-crash-diagnostics/artist/)；先于应用代码实现绘制。图为布局设计，实际 provider/主题仍需真实 Compose 验收。

## 数据、图片与边界

Room 34、45 表、备份 16 不变，无迁移。只在 noBackup 独立诊断目录写小文件；不枚举业务数据，不读照片，不进入公开服务。捕获后仍调用原系统崩溃处理器，不吞异常或恢复损坏状态。写诊断失败不能阻止系统原有处理。OOM 下本机写入只能尽力，系统退出原因可补充但不能保证每种退出都有 Java 栈。

## 验收

- 纯 JVM 验证原因/抑制异常/循环/上限、不泄漏消息、失败仍委派原处理器和覆盖规则。
- 独立 AVD 验证真实子进程未捕获异常、重启读取与系统退出原因；真实 SAF 导出/取消，文件只含允许字段。
- 新菜单七皮肤浅暗、320dp 两倍字；广场地址打开/输入/取消继续回归，短窗口与配置重建只代表 AOSP 窗口压力覆盖，不冒充小米复现。
- 原签名正式包覆盖 2.78.1，核对当前基准数据/图片/设置保全；双平台正式附件、SHA、匿名下载与更新入口按项目流程验收。

交付必须标为诊断补丁，不宣称已修复该手机两处闪退；需要实际手机复现后主动导出的记录来继续定位。
