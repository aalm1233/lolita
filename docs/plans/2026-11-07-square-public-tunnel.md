# 广场公网 HTTPS 接入

## 目标与采用方案

内网 SQLite API 已完成验证，本轮通过花生壳长期引擎将独立服务 `127.0.0.1:18765` 映射为 `https://f8b8b6fa0e0f.eicp.fun`。用户确认 TP-Link 当前配置为动态 DNS；未改路由器配置。公开接口仅含已核验商品目录与原图，不映射文件目录、SQLite、采集证据或写入工具。引擎常驻、映射长期有效，沿用账号现有授权，无付费购买。

用户已完成官方登录授权和本机管理员安装。账号凭据、节点内部标识及系统服务配置留在仓库外。手机关闭 Wi-Fi 后用移动流量访问 `/v1/health`，用户确认返回 `lolita.square.api`。宿主机公网接口、分页及图片 SHA 已核对；Mac 本机代理虚拟 DNS 路径存在间歇 TLS 异常，公网 DNS 解析路径单列记录。Android 实际同步、原图与离线心愿仍待验收，不能由健康接口代替。独立 Android Java 探测显示同域名首次健康请求成功、第二次请求超时、第三次目录请求成功，正在对照连接复用与显式关闭连接；显式关闭连接后独立探测连续成功；仓库完整同步仍遇短超时，因此采用7.5秒连接/15秒读取上限，并以直接客户端与仓库链路分别验收。

## 实施顺序与界面适用范围

1. 确认真实公网协议、完整目录、详情、缩略与原图，以及写方法/文件路径拒绝；区分外部手机、宿主机与模拟器证据。
2. 检查 Android 请求失败类型，按实际证据修复必要的公网连接兼容；通过真实网络后切换内置根地址。
3. 执行定向构建/回归、正式签名覆盖安装、双渠道发布与实际更新检查，归档最终结果。

复用 2.77.0 广场服务弹窗和“使用内置地址”按钮，仅改变默认地址及实际需要的传输兼容。没有新页面、导航、图标、布局或皮肤构件，沿用 `2026-11-07-square-developer.md` 的前置图稿；本轮无需新增艺术图及未改页面的七皮肤矩阵。长地址仍须在现有输入框与真实页面核对。

## 数据、图片与失败边界

- 已保存的自定义地址和明确空地址继续优先；缺省设置使用新 HTTPS 根地址，保存内置地址仍由现有设置入口完成。
- 保持 HTTPS 证书/主机名校验、禁止重定向和公开地址强制 HTTPS；不能以关闭证书验证解决网络失败。
- 前台及下拉刷新继续沿游标读取；连接失败静默、保留缓存，不阻断衣橱。图片继续缩略按需、原图按 SHA/字节/尺寸验收，私人心愿保存独立 UUID 原图。
- Room34／45实体／备份16不变，不迁移私人资料、账本、备份或缓存；不新建采集调度。

## 验收选择

只覆盖地址默认/配置兼容、实际公网目录与图片、静默失败和离线心愿。沿用 `SquareNetworkTest` 的独立 Room／缓存／设置，通过 `squareServiceUrl` 参数访问真实 HTTPS。JVM 根据最终代码差异选择协议/浏览相关类，不跑全量。若仅默认常量变化，无需重复无关数据库全表或图片清理审计。正式包仍执行 clean Release、原签名覆盖冷启动、素材核验及 GitHub/Gitee 同 APK/SHA/更新入口检查。

2项JVM与7项去重Android定向方法通过；真实公网完整目录、缩略/原图、离线心愿、配置兼容和静默失败已验收。正式签名覆盖与双渠道发布结果以[实施记录](../square-public-tunnel-implementation-2026-11-07.md)及最终发布回执为准。
