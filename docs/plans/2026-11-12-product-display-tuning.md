# App单品展示生成调优

用户要求把上一轮研究落实到App，继续使用原500次火山请求上限及同一独立账本（开始时已用121，余379）。本轮交付生产代码、实际服务对照及正式版本，不能只交评估报告。

## 现状与采用范围

批量展示的非人台分支目前调用旧素材主视提示，单件入口调用MannequinRequest，两者不同；前轮全头假发去头模候选未覆盖常用批量路径。新建独立展示统一提示构造，按稳定类型区分完整假发、发片、玩偶、鞋袜及其他配饰，并使用当前物品名称和组合身份帮助选择目标。名称仅作数据，不允许把描述当指令或补造不可见结构。可见一只不凭PAIR补另一只，成双可见部件不合并，链条／空隙／细绳和长发边缘须保留。

先冻结当前批量提示对照，在同一参考图上比较候选，依据逐图结果收敛；改善须体现到实际生产提示与任务快照。固定裙装/衬衫人台和独立假发头模保持原目标，旧素材分层流程不改。不开启三视图，不增加额外分析或第二阶段，不自动重试，不增加每件输出数。

## 设计适用项

主要调整后台提示构造与新建请求；既有费用说明原位补充将发送名称、类型、颜色、组合和补充要求。既有分类说明/图片模式文本原位显示本次冻结的实际名称、颜色与组合，供发送前核对；不新增入口、控件、页面或图标，不重新设计布局，因此无需新艺术图稿。说明和数据换行以真实七皮肤浅暗及小屏大字实页检查。既有输入对照、完整Fit/放大、用户确认后追加相册及主动设封面沿原设计。实际页面核对新任务核对/保存、模板与非模板路由，不能把主机真实调用当作Android端到端通过。

Room34、45实体、备份16不升级。新任务仍冻结提示全文、实际输入SHA及当前模型；旧请求的快照与历史重试不被新构造重写。原照片和封面不改，私有输入与输出留仓库外，只提交通用规则和脱敏汇总。费用继续为每件一次已确认请求，无隐含重发；实际付费账单与请求计数分开。

## 执行与验收

1. 冻结现有批量路径提示并确认当前任务/备份约束。
2. 以同一参考生成当前与候选对照，逐张检查头模残留、目标、数量、空隙、附属件、长边及裁切；按结果收敛。
3. 接入新建单品/批量请求，验证旧快照不变、输入冻结、单次调用、保存与备份往返。
4. 定向JVM和设备测试、Debug构建；提交后归档clean原签名Release、同签名覆盖和资料保全，双平台发布与下载核验。

本轮具体真实次数、采用规则和未通过边界以最终实施回执为准，不把三款头模移除改善表述为全品类保真通过。
