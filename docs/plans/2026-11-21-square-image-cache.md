# 广场缓存图片复用

用户要求：刷新广场时复用已缓存图片，减少加载与流量。

## 现状与采用方案

`SquareRepository.refreshSilently` 已按游标更新目录，图片按需下载。下载层已有原图 SHA/字节校验、缩略图落盘及同路径互斥，并非每次刷新都无条件重新下载；但列表 `thumbnail()` 只识别本地原图，没有识别已落盘缩略图。刷新递增 imageEpoch 后，已缓存缩略图仍生成新 URI，绕开原有内存缓存并重复进入 fetch/decode。

本轮让列表优先使用已存在的原图，其次使用非空的持久缩略图路径；两者都不存在时沿用带刷新代数的远程占位，保留失败重试。内容寻址文件名保持，目录更新引用新 SHA 时自然加载新图，不按时间让旧缓存过期。下载层的校验、原图按需下载、并发锁和清空保护保持。

这是纯后台缓存选择优化，没有界面、布局、皮肤或新入口变化，不需要新增艺术图稿、七皮肤或键盘矩阵。现有列表 Fit、详情完整原图及放大规则保持。不会用缩略图冒充收藏所需原图。

## 数据、隐私与发布

Room34/45实体、备份16、私人图片引用与保存规则均不变。兼容原有 thumbnails/<原图SHA>.webp 与 images/<SHA>.<扩展名>，无迁移、清缓存或费用调用。图片仍只从配置的只读服务获取；失败静默并保留旧文件。

按项目约定递增为2.78.13/169，提交后由隔离的源码归档构建 clean 原签名 Release，并完成双平台分发和更新入口核验。

## 验证计划

使用独立AVD、隔离Room/目录和带请求计数的本机HTTP服务，验证：

- 首次按需下载后，连续刷新使用相同的缩略图路径和Coil内存缓存，图片请求不增加；重建仓库及离线仍可读取。
- 缓存原图优先，完整原图与缩略图分开按需下载，反复刷新/重入不增加图片请求。
- 缺失/零字节缩略图仍可刷新重试，错误响应不落为有效缓存。
- 同图并发请求只下载一次；目录新增内容SHA后只获取新图并保留原缓存。

Debug/定向设备方法、正式签名覆盖2.78.12两次启动、项目素材与双平台同APK完整下载/SHA/HEAD分别记录。仅验证受影响缓存行为，不重复无关UI与全库迁移测试。

## 实施与定向结果

已完成本地原图/非空缩略图优先选择。新设备测试`SquareImageCacheTest`使用实际HTTP请求、Coil解码及独立Room：旧实现先在“缓存缩略图应直接解析为持久文件”断言失败；最终4个方法全部通过，Debug及AndroidTest构建通过。

缓存缩略图首次请求1次、连续5次目录刷新后仍为1次，后续解码命中MEMORY_CACHE；关闭网络、重建仓库、清空解码内存后从DISK成功读取，原图请求0次。原图按需单独获取后两类入口都直接复用原图，关闭网络再刷新5次无新增图请求。同图12个并发调用只下载1次，新SHA更新仅新增新图请求1次；无效图片/零字节缓存仍能重试且不会替换有效图片。此为受控服务验证，不声称特定公网时延或节流百分比。
