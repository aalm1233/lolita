## 范围

v2.39.2 发布后，以 d96f239 为基线审查剩余改动；仅修复和提交经过审查的运行逻辑、验证工具及对应文档。既有私人工具配置、草稿和纯换行差异保留。

## 确认问题与修复

| 问题 | 触发与后果 | 修复 |
|---|---|---|
| 付款页面闪退 | 阶段与实付各自自增的 ID 相同，同一 LazyColumn 使用重复 key；首屏或滚动闪退 | 两类列表 key 增加不同前缀，保留数据库 ID/金额；真实 Compose 同屏和往返滚动回归 |
| 提醒分钟丢失 | 选择 20:45 却保存为 20:00，20:15 设置可能推迟到次日 | 配置原子保存时分；旧配置默认分钟 0；从完整最新配置重排 |
| 无通知权限仍开启 | Android 13+ 新装只开启穿搭提醒，没有申请权限，长期没有通知 | 开启前申请权限；拒绝、应用总通知关闭或穿搭提醒渠道单独关闭时说明并提供对应设置入口 |
| 过期广播及同日重复 | 关闭或改时间后已发出的旧广播仍通知；当天改时间可能再次提醒 | 校验最新配置、日期和时区；成功投递后写本地日期回执；已有今日记录时跳过 |
| 点击通知没有快捷入口 | Intent 已带快捷穿搭参数，Activity 未消费 | 冷/热启动统一消费并导航，旋转/恢复不重复打开 |
| 日历只写权限被当成完整授权 | 删除旧事件后，查询日历因缺 READ 失败，新事件未创建 | 创建要求 READ+WRITE；删除保持仅 WRITE |
| 日历提醒失败仍报成功 | Reminder 写入失败但事件 ID 被保存为成功，只有事件没有提醒 | Events/Reminders 同批提交，真实失败保留恢复日志重试 |
| 日历访问级别误判 | 只排除 READ，误选不可写主日历而错过可写次日历 | 最低要求 CONTRIBUTOR，优先可写主日历 |
| 自动化可能误报与误选设备 | 默认 ADB 可能作用于错误模拟器；dump/pull 路径不一致；FAIL 最终退出 0；旧导航及无证据 PASS | 明确设备与分辨率，实际证据验证，失败退出非零；未执行标记 SKIP |

`AppModule` 保留 applicationContext 的改动合理。数据库结构和备份格式保持 schema 23 / format 5；本轮不改购买证据或生成实际付款。
