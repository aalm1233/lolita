# 页面上下滑动修复（2.40.2）

## 原因与范围

1. `SkinFlingBehavior` 的 `animateDecay` 回调使用 `value - animationState.value`；两个值都已经更新为本帧位置，造成位移始终为 0。除使用原生惯性的中式皮肤外，其余六套皮肤会在手指松开后停住，并在边界继续空转。位置、套装、穿搭、统计等使用此公共实现。
2. `SkinItemAppear` 在 composition 中读取动画进度。真实回归中，推进 8 帧时卡片重组次数从 1 变为 9。
3. 原全局滚动 Boolean 只有首页服饰列表的三个分支写入；位置、套装、穿搭、统计未上报。粒子背景在这些页面滑动时仍持续更新。首页滚动切换还会重置全部粒子并隐藏画面；不同列表直接写一个 Boolean 存在互相覆盖及离开页面后遗留状态的风险。
4. 穿搭、心愿和服饰画廊逐卡片调用整个列表的 `indexOf`，造成随列表规模增长的扫描成本。

## 实现

- 惯性使用独立上帧位置计算 delta；原始释放速度经皮肤摩擦衰减，不额外放大。遇到未消费位移时及时结束并返回余速，支持父容器接续。
- 卡片入场的进度、透明度、位移和缩放均在 `graphicsLayer` 中读取/更新，保留视觉效果。
- `SkinScrollActivity` 按独立来源合并状态；`ObserveSkinScroll` 只订阅 `ScrollableState.isScrollInProgress` 的开始/结束，取消时移除自己的来源。位置、套装列表及网格、穿搭、首页心愿、统计总览、付款年历、消费分布/趋势、愿望分析、服饰列表及网格/画廊和首页/统计 pager 接入。
- 粒子按实际 Canvas 尺寸初始化，帧时钟与实际经过时间驱动，粒子节奏最高约 60Hz；滑动期间冻结可见画面，恢复后从新的帧基准继续，不重新随机初始化。长帧最多按 100ms 更新，避免跳跃。旧时钟已在绘制阶段读取，本次没有将其误归因为整个导航树逐帧重组。
- 穿搭/画廊/心愿用 `itemsIndexed` 获取当前索引，保留稳定 ID key 与预览/详情导航参数。
- 不修改数据库结构、价格、付款、历史证据或备份格式；仍为 schema 23 / backup 5。

## 验证方法

- `SkinFlingBehaviorTest`：真实公共组合函数取得七套皮肤的行为，双向释放后位移非零；边界最多 3 帧结束且余速不大于输入。旧代码得到 0 位移、边界空转 219 帧，两个用例均失败。
- `SkinItemAppearTest`：真实 Modifier 与手动 Compose 帧时钟，入场期间只更新图层，不重组卡片。旧实现 1→9 次重组，修复后保持不变。
- `SkinScrollActivityTest`：多来源停止/移除互不覆盖；真实 `ScrollState.scroll` 取消及观察者离开后清理。
- `SkinBackgroundAnimationTest`：真实 Canvas，滑动持有期间不自行请求重绘，结束后恢复。
- `ScrollPageTest`：独立内存 Room、UUID DataStore、本地 PNG 与 48 条合成资料，实际位置、套装列表/网格、穿搭、统计页面；验证拖动、松手后真实视口继续移动、惯性结束/页面移除后恢复背景以及详情/筛选导航。
- Android 回归定向运行在自建 `Lolita_Business_Fix_Test`（emulator-5556），不使用包含用户数据的 emulator-5554。
- 正式包在自建 `Lolita_Release_2392_Test`（emulator-5558）使用同一组 48 个位置、48 个套装、48 条穿搭、192 件服饰和 4 张本地图片验证。按 UI 树定位页签，每页执行 8 次相同坐标、600ms 的上下拖动，保存截图、UI 树与 `dumpsys gfxinfo framestats`。模拟器指标只作为此设备、此数据和此次运行的观察，不代表实体手机的掉帧率。
