# 采集直接形成广场资料包

用户希望后续拉取最新淘宝店铺资料时直接得到App所需格式，并指定魔女贩售、zjstory、OZZonjapan实际走通。主助手始终不访问淘宝；页面访问和原图下载仅委派给本机dsh的DeepSeek。

## 已采用流程

`prepare → dsh采集原始文件及square-input → 本地原图审读 → package → App ZIP + quality.json`。

维护源为`skills/taobao-shop-updates/`，全局技能安装目录保存同一源的副本。prepare附本机目录基线和紧凑店铺/动态/商品身份索引，具体SKU身份在按商品拆开的文件中按需读取，避免让模型一次吞入全部旧图/规格。已有三店浏览版作为基线，SHA已核验；后续沿用店铺、设计、批次、商品、部件与规格身份。

dsh需输出完整原始JSON、逐SKU CSV、原图清单及相对路径；App输入明确四类动态、实际SKU、单品/小物/商家套餐、各件色码、独立照片、参数、风格依据、尺码表与来源。未知不靠整搭图或套餐价填补。覆盖状态不完整或无法归类放deferred，缺独立图保留空映射，成功店仍可交付。

本地工具对照原始完整SKU/报价/图片集合，计算SHA和尺寸，检查同商品图片引用、表格行列、证据文件和公开字段，再合并旧目录。模型不决定revision；同内容保留版本、变化才升版，只采集时间变化不算businessChanged。旧记录本轮没出现仍保留，不能据此判断下架。

候选ZIP经**实际App Kotlin源码**的decode/validate/unpack路径验收（本地编译，不另写一套假想App规则），通过后才发布文件和原子更新current.json。并发或基线变化时拒绝陈旧请求；失败、坏图、缺图或超限不推进。ZIP只含公开manifest和SHA原图，不含OCR、原始页面、日志、认证信息或私人物品协议。
