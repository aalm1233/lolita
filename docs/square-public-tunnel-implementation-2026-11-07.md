# 广场公网 HTTPS 接入

采用[前置范围与实施计划](plans/2026-11-07-square-public-tunnel.md)。内置地址由内网地址切换为 `https://f8b8b6fa0e0f.eicp.fun`，花生壳长期系统引擎仅映射 `127.0.0.1:18765` 的原只读 API。原 SQLite、公开目录、采集入库链路均保留，路由器原动态 DNS 未修改。电脑、引擎与 API 需保持运行；引擎随系统运行，API沿原用户LaunchAgent运行。本轮未购买服务、未创建采集定时任务。

前台及下拉刷新、按需缩略/原图、完整 SHA/字节/尺寸校验、心愿独立UUID图片继续沿原流程。自定义地址和明确停用配置不自动改写；曾主动保存内网地址时，可在广场齿轮点击“使用内置地址”后保存。Room34／45实体／备份16、私人衣橱与账本不变。

真实 Android 对照探测发现复用连接时连续请求超时；显式 `Connection: close` 后连续健康与目录请求恢复。内网连接/读取2.5秒/4秒参数在完整公网同步时仍触发SocketTimeout，改为7.5秒/15秒上限。证书、主机名、禁止重定向与容量校验未放宽，没有自动重试；请求仍在IO协程，失败仍静默并保留缓存，不阻断其他功能。

只有地址默认值和传输兼容变化，没有新布局、组件或皮肤构件，复用2.77.0的设置设计。按影响范围选择2项 `SquareNetworkConfigTest`，以及7项真实 `SquareNetworkTest` 方法，包含新增直接客户端连续读取全分页/原图、仓库并发刷新与重启、缩略/原图/离线心愿、旧配置/停用、异常游标/坏图和错误静默。独立Room、UUID设置及缓存不使用用户手机数据。

公网服务端验证：7店／15动态／31商品，游标15；公网与内网协议、全分页和商品对象一致，三类新增商品各一张缩略/原图经SHA与尺寸验证，数据库/原始证据路径404、写方法405。宿主机代理虚拟DNS路径的间歇TLS异常与公网解析路径分列记录；未修改系统代理或DNS。用户在关闭Wi-Fi的手机流量网络打开健康接口，确认返回 `lolita.square.api`，该证据只覆盖健康接口，不冒充手机端完整商品/图片测试。

Debug与androidTest构建、2项JVM及7项去重Android方法通过。坏响应夹具原来仅响应两次，页面会追加刷新，已改为持续响应至关闭；该方法修正后单独通过，其余六项在相同产品代码下已通过。正式签名、覆盖启动和双渠道发布将在完成后归档至 `docs/square-public-tunnel-release-2.78.0-verification.json`，当前不代表正式发布已经完成。
