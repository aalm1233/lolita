# 广场单品资料与物品详情 · 2.73.1

用户实拍的问题是筛选占屏、系列图片与具体单件混用，以及物品详情层次不清。本轮先由艺术家完成六页流程与七皮肤浅暗，再实现原生页面；使用本地三店公开档案，全程未访问淘宝、未上传资料、未调用付费服务。

## 实现范围

- 广场去掉重复大标题，把动态改为紧凑Tab，店铺与属性筛选共用一行；图片180dp完整Fit，首屏提前显示商品名称。商品页独立展示具体部件和对应资料，完整系列图片仍可按原角色浏览、放大，长来源按需展开。
- 先选实际完整SKU，再勾选实际包含的部件；可分别登记，也可把所选子集合合成一个物品。自由组合的名称和类型可改为服饰组合、小物组合或套装，组成沿用成组身份，不自动创建衣橱套装或主件关系。
- 每个输出分别选择主图/资料图、设置封面；图库可从全部、规格、详情或模特主图筛选，来源图角色与本次存放角色分开。明确SKU图片和人工核验资料作为建议，缺失映射保留未知，不自动给每件整搭图/全链接详情。原图保全，图库放大使用完整文件。
- 逐件进入原编辑器，默认心愿，正式保存才写Item。已准备的ItemDraft持久化，紧凑选择和处理进度由SavedStateHandle恢复；同一导航状态可继续上次登记。关闭整个任务后未准备的后续件不承诺恢复。整体/单部件沿用旧importToken；自选子组合按排序部件集合生成稳定身份，重入打开原草稿或原记录。不是原子多件保存。
- 物品详情统一标准顶栏、受限180—248dp Fit主图与ImageFrame，品牌和完整名称、拥有状态、原购买摘要依次呈现。保留设封面、编辑删除、主件小物、尺码图、补资料及原价格/付款导航。广场来源折叠呈现；原用户备注、旧图片与账本不改写。小屏大字体将购买摘要标题和入口分行，选图的名称/组合设置收起，按钮文案缩短。

## 数据、兼容与隐私

Room34/45实体、备份15不变。仅公开包增加可选`SquareSku.photoPaths`、`SquareProduct.materials`；字段缺失的旧v1包继续浏览与手动选图。高revision更新公开记录，不反写旧Item。商品内图片引用、范围、数量与80MiB副本上限复核。每件选中图片经ImageFileHelper复制成独立UUID文件，失败清理未引用副本；ItemDraft显式相册/尺码图列进入现有ZIP/JSON，原有图片保护和CSV方式不变。

次件没有单独说明的颜色/尺码留空；只保留原规格报价快照，不自动写本件参考价、订单、实付或分摊组价。公开目录与私人备份分离，不增加联网、账号、云同步和付费行为。既有金额隐私与账本摘要计算保持。
