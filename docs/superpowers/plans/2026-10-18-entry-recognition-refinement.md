# 录入与识图减负改造

用户反馈：柜架按钮换行、登记信息过多、识图层级过深，豆包请求反复报“无法核验”。本轮直接修正这些问题；不删除原资料、不扩展账本或数据库。

1. 先复现并定位错误，归档[实现前界面图](../../visuals/entry-refinement-2026-10-18/preview.html)，七状态×七皮肤×浅暗，并检查320/360宽度、1/1.3/2字号与键盘。图稿是界面设计，不冒充实际应用或付费结果。
2. 登记默认突出照片、名称和类型，常用尺码/颜色/位置可直接填，规格备注与品牌/风格/来源/关联按需展开。已有值保留并显示摘要；状态与共价、历史订单约束保留。唯一文字保存按钮放底部并适配IME；常规返回保留草稿，明确放弃仍有入口。
3. 识图使用编辑器内一个全屏工作面，默认整图、框选可选，实际JPEG预览和显式付费发送同屏。结果简洁核对、可展开来源，填入后返回编辑；历史和密钥管理不占主流程。服务/Key/图片改变使旧确认失效，不自动重发；已确认业务值、价格、证据、来源和冻结请求边界不放松。
4. 柜架与移入操作通栏、自然高度，完整文案在小屏/大字下保持可读，不靠截字掩盖布局问题。
5. 豆包失败先用现有真实结果与受控响应重放，区分传输、信封、结构解析和候选可用性，修正可兼容的真实协议差异。不能通过伪造单位/明文或放开敏感字段来让测试通过。原图不改，裁切输出继续UUID和引用保护。新一轮真实付费测试另按本轮明确额度执行，旧18/20不沿用。

实施分工：编辑与规格、柜架布局和回归、识图协议与真实响应复现并行；根代理负责前置图、识图工作面整合、数据/草稿边界复核与最终构建、独立AVD对照及正式发布。Room30、备份10预期不变，旧任务及所有已保存字段按原语义读取。必要测试覆盖真实输入、错误恢复、已有/新建资料、小屏大字键盘、七皮肤浅暗及同签名升级。
