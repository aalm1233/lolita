# 虚拟试衣实验功能

## 已确认的目标

用户希望衣橱内的服饰穿到固定虚拟模特身上，预览整套搭配。已认可“花鸟龙月”单裙、短外搭，以及发箍、短款手袖、链条腰带的两轮参考样片。用户已指示 GO，并选择接入推荐的官方服务。

## 实现决定

以下为实现者选择：首版使用 OpenAI 官方 Images API 的多图编辑，默认 `gpt-image-2`；每次只生成一张图片。Android 使用个人自行配置的 API Key，经 Android Keystore AES/GCM 加密保存在 noBackupFilesDir。APK、日志、数据库及业务备份不含密钥。不配置共享开发者密钥，不建设收费后台。

入口为个人页“虚拟试衣 · 实验”，另在服饰、套装详情提供带预选的入口。固定成年女性模特采用生成的中性站姿参考图，随应用离线提供。每件服饰使用用户指定的一张原图，最多八件，均明确角色（主件/内搭/下装/外搭/头饰/手饰/腰饰/其他小物），角色可纠正；同一服饰不重复选择。名称搜索、分类筛选不清除隐藏选择。只上传模特与明确选中的图片，不上传账本、备注、品牌资料、整份备份。

## 使用流程

1. 进入实验页，看到固定模特、用途说明与已保存试衣图。
2. 从衣橱搜索选择服饰和小物，逐件选择参考图与角色，可移除。无图服饰不能生成；至少一件服装主件，最多八件。
3. 本机配置页输入个人 API Key。保存后只显示已配置状态；输入框不回填密钥。可清除密钥。
4. 生成按钮旁明确显示将发送到 OpenAI 的图片数量、可能计费及实验性质。用户点击才发出请求。
5. 生成中冻结选择与服务配置，显示真实阶段（准备图片/生成中/保存），不伪造百分比；阻止重复点击，可取消等待。取消或超时提示服务端仍可能处理，重试由用户主动触发。
6. 成功后自动保存独立试衣记录并预览，可全屏放大、重命名、删除。记录保存服饰 ID 字符串与名称快照，原服饰之后删除不影响历史图。试衣不会改变套装归属、穿搭次数、实付或统计。

## 持久化与兼容

新增 Room `TryOnResult`、DAO、薄 Repository，并接入 LolitaDatabase 和 AppModule；数据库 26→27 只新增表。结果含 Long id、名称、UUID 本地结果图路径、服饰 ID/名称字符串列表、模型版本与创建时间。复用现有 List<String> 转换器。图像统一由 ImageFileHelper 保存/清理，新增记录引用保护。

备份格式 6→7：JSON/ZIP 导出、解析、图片清单、路径映射、恢复校验、预览、CSV 同步添加试衣结果。格式1–6缺失结果兼容为空；新格式要求数组完整。密钥不导出。导入试衣记录的服饰 ID 是历史快照，不是外键，不要求原服饰仍存在。

## 网络与失败边界

仅调用固定 HTTPS 官方 endpoint `https://api.openai.com/v1/images/edits`，禁用重定向；multipart 按顺序发送模特＋所选服饰图片，生成提示词明确索引与角色，不把用户名称当成指令。图像规范化长边≤1536、JPEG质量90，每张≤10MiB、总输入≤40MiB，原图片不改变；请求固定 n=1、quality=medium、size=1024x1536、output_format=png，不自动重试付费请求。

只接受非空合法 Base64 图片响应，限制响应与输出大小并实际检查图片尺寸。HTTP鉴权、额度、限流、超时、无图等显示中文错误，不暴露响应中的敏感文本。取消中断连接，未提交记录的输出清理；保存成功后不因导航取消而删除结果。图片保存与 Room 提交失败不留下孤儿；全局互斥避免两个入口并发发起生成。

API Key 是当前实际联调的外部条件：本机环境未配置 OPENAI_API_KEY。可先完成实现、可控传输回归与设备验证；不得宣称真实官方接口试衣已验证。

## 视觉与验收

复用七皮肤 LolitaCard/LolitaSection/SectionHeader/GradientTopAppBar/LolitaShimmerImage、皮肤间距和圆角；不新增图标，使用现有服饰/图片/设置/删除等语义。懒列表接 ObserveSkinScroll。选图与配置在小屏、大字体、暗色下可达。

必须通过 assembleDebug、单测及独立 AVD 的 Compose/Room 回归：选择及换图、角色纠错、重复提交、失败保留选择、成功历史/删除、图片引用保护、密钥不明文/清除、26→27迁移、旧备份/新版ZIP往返，以及七皮肤浅暗布局。正式发布遵守 AGENTS.md 的 clean Release、签名、覆盖升级资料保全和双平台附件摘要规则；真实官方生成未完成时明确报告这个限制，不冒充已实测。
