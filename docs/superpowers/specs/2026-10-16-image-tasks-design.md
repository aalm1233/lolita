# 后台图像任务与版本说明设计

日期：2026-10-16。状态：待用户审阅；功能范围已确认，具体实现选择由开发者提出。

## 需求与成功标准

用户确认当前即梦生成功能可用，但生成期间页面和底栏被锁住。要求将虚拟试衣、裙子正面人台图改成异步任务，并增加任务中心查看进度；检查更新需要展示最新版本内容。用户进一步明确：离开页面、锁屏后继续，重启后保留任务记录。

提交一次生成后立即可浏览应用、返回、切换底栏、再次进入任务中心。任务由应用后台服务持有，不依赖页面 ViewModel 生命周期。任务和待确认人台预览在进程重启后仍可查看。这里只承诺保存记录；无法在系统强制停止、关机或进程被杀后无条件继续远端请求。

继续使用 Kotlin / Compose / Room / 手写 AppModule，以及现有即梦和 GPT 官方接口、模板、图片校验、加密密钥和付费确认。原始服饰、价格、订单、穿搭、图片顺序和试衣历史必须保全。

## 用户流程

1. 生成页保留选图、服饰/小物选择、补充说明、服务配置及本次调用说明。确认后提交一个持久任务，显示“已加入任务，可离开页面”及“查看任务”。短暂提交期间防止同一按钮双击重复建任务。
2. “个人”增加“任务中心”入口；两种生成页均提供任务入口。保留四个底栏，不新增主导航。生成页显示最近一次提交的任务状态，但不拥有或清理任务结果。
3. 任务中心默认按创建时间倒序，进行中和待确认任务优先；显示类型、服饰/搭配名称、服务、创建时间、真实阶段、错误和适用操作。状态筛选为“全部 / 进行中 / 待处理 / 已结束”，使用现有皮肤组件和中文文案。具体图标、布局细节由实现者按现有组件决定。
4. 任务状态包括排队、准备图片、生成中、保存结果、待确认、已完成、失败、已中断、已取消/已舍弃。远端接口不提供真实百分比，因此显示阶段及不定进度，不伪造 50%/90%。服务通知显示当前阶段和排队数量；点击通知打开任务中心。
5. 试衣成功仍自动写入独立 TryOnResult 历史；任务中心可查看完整 Fit/放大结果。删除任务记录不删除已保存试衣历史。
6. 人台成功停在“待确认”，任务中心可查看完整 Fit/放大预览，明确点击“添加到裙子图片”才追加到该裙子末尾，也可舍弃。离开页面、进入别处或重启都不自动舍弃。原裙子删除后仍能查看预览并舍弃，但不能添加到另一件裙子。
7. 排队任务可直接取消；运行中取消需要确认“停止等待可能仍会计费”。失败/中断/取消不自动重试，用户主动重新发起且再次确认后创建新任务，保留原记录。请求参数失效时引导回生成页核对，不绕过最新资料验证。
8. 可删除已结束记录；待确认预览删除需明确确认并清理未引用图片。正在运行不能直接删除，需先取消。暂不增加批量删除、远端进度查询、批量自动生成或任务优先级。

## 后台执行与费用边界

开发者选择使用直接的 Android 前台服务（dataSync）承接用户主动发起的图像上传、云端处理及结果接收；不引入 WorkManager 自动重调度。官方 dataSync 支持设备与云端的数据传输；Android 15 的后台时限和启动限制必须处理。前台服务提供持续通知、限定时长的 PARTIAL_WAKE_LOCK、有限网络超时、及时停止和 onTimeout 回收。通知权限未授予时不阻断提交，说明可在任务中心查看；复用现有通知权限机制，不循环申请权限。

一个服务串行执行持久队列，继续共享进程生成互斥锁；多个任务可排队，每个任务对应一次明确确认。页面提交和服务启动之间的短暂异步交接由应用级作用域负责，页面退出不能丢失已接受的任务。启动失败必须写入可见的失败/暂停状态，不能静默显示一直生成。正常队列耗尽即停止服务、释放锁与通知；不从 BOOT_COMPLETED 启动付费生成。

提交时冻结服务和请求快照，不把 Key 写入任务、Intent、SavedState、日志或备份。执行时按任务的服务读取该服务最新本机加密 Key，一次性捕获后贯穿本次请求；之后用户切换服务不会更换已提交任务的计费方。缺少 Key 则在上传前失败。允许在别的页面配置服务，不再用全局“生成中”锁住全部界面。

网络请求发出前必须先持久化“生成中/请求可能发出”的状态，再调用 API。单个任务须以数据库条件更新领取，服务重复启动、重组和双击不得重复领取。状态写入必须有序，不能用未等待的协程更新关键阶段。

服务为 START_NOT_STICKY。应用下次启动，先完成恢复，再允许新提交/领取：原先活动及尚未开始的排队任务转为“已中断/待重新发起”，保留是否可能已请求的提示；不会自动再次产生付费请求。已完成及待确认任务保持。进程在结果保存边界退出时，应恢复已持久化结果而非重复请求：试衣结果与任务完成在同一 Room 事务内提交；人台预览的持久引用与待确认状态原子提交。文件已写入但数据库未提交的短窗口只能产生可清理的未引用文件，不能导致重发。

取消、超时、服务被系统停止均不能声称远端取消成功或不会收费。不得为测试新增真实付费调用；外部 API 用受控传输验证。

## 数据与并发

Room 27→28 仅追加图像任务表，已有表和记录不改写。任务包含稳定 UUID、请求类型/版本、服务、名称与物品快照、参考图片、说明、状态、创建/更新时间、结果引用及受控错误；具体列和结构由实现者决定。新增枚举补 TypeConverter。DAO 同时接数据库、薄 Repository 与 AppModule；执行、恢复及状态机放独立领域/协调层，ViewModel 只观察 StateFlow 和发起操作。

原图在执行前继续复核当前 Item/Category/拥有状态/图片归属和文件完整性。排队期间图片变化或服饰删除则明确失败。必要的队列源图和待确认结果纳入 ImageFileHelper 的持久引用保护；结束后解除临时源图引用并清理不再被任何业务记录使用的图片。

确认人台预览与任务状态更新在同一数据库事务中读取最新任务和最新 Item，仅追加图片/修改时间，幂等防重复保存；保持已有 ItemRepository.appendGeneratedImage 的最新行更新保证。并发确认/舍弃/删除只能一个成功，失败不丢预览。短暂保存操作由应用级作用域持有，页面退出不取消提交。历史任务不能借路径接管或删除应用目录之外、其他任务或已经保存的文件。

已完成任务引用业务结果；删除任务不删除 Item 图片/TryOnResult，删除业务记录后任务可显示“原结果已删除”，不复活业务数据。待确认预览由任务唯一持有，舍弃/删除通过统一引用保护清理。

## 备份兼容与恢复

任务记录、待确认预览进入备份，格式升级 7→8 / schema 28，旧 1–7 缺少任务数组补为空；相应补导出、导入、预览数量、图片清单/重映射及适用 CSV。结构化解析请求快照并重映射路径，不对 JSON 文本做路径替换。Key 和后台服务运行状态永不备份。

备份中的排队/活动任务恢复后转为已中断，不启动服务，不上传照片；待确认人台预览可继续明确确认保存，完成试衣继续引用原结果。校验任务类型、枚举、请求版本/限额、结果归属和本地图片；未知或损坏数据必须拒绝，原有备份数据的逐字段验证继续保持。

导出允许读取一致快照，不等待远端生成。导入替换业务数据库前必须通过协调层暂停队列、取消当前等待并等待本地写入退出，与确认保存串行；取消发生在请求后须保留计费提示。恢复失败不能误删原业务或待确认文件，恢复成功不能让旧协程把结果写入新数据库。原有串行备份锁和初始化屏障不能形成反向等待。

## 检查更新的版本内容

AppRelease 增加默认空的 releaseNotes，Gitee 正式版本列表同一次请求读取最高稳定版本的 body；兼容缺失/null/空正文及既有构造调用，不另加网络请求。遗留 GitHub 解析器同步支持正文，保持兼容。

更新对话框在版本号下展示“本版更新”及完整可滚动说明；无正文显示“此版本暂未提供更新说明”。手动检查即使已是最新版也能阅读最新说明，自动检查仍只在有可下载新版时提示。正文作为不执行 HTML 的文字展示，可去除常见标题/列表标记改善阅读，但不依赖新的 Markdown/WebView 库。沿用既有正文总量、网络时限和可信下载地址限制，长说明和大字体不能挤出下载、关闭、重试按钮。
