# 专属试衣模特设计（2026-10-16）

状态：讨论稿；用户已确认核心方向，完整方案经独立 builder check 无关键待决问题，待用户审阅方案与页面草图。尚未开始产品实现。

## 已确认的需求

- 用户希望基于身体参数和照片，捏出每个人自己的试衣模特。
- 输出照片式的全身模特图。
- 有本人照片时，脸和身材都尽量像本人。
- 只有参数时，生成相应体型并使用虚拟人脸。
- 用户要求同时查看页面草图。

以下流程、字段和技术选择为实现者建议，尚不视为用户已逐项认可。

## 使用目标与边界

生成一张用户认可的标准全身底图，保存为可重复使用的专属模特，再把现有虚拟试衣的内置人物替换为选中的专属模特。试衣直接使用已确认底图，不在每次换衣时重新按参数造人。

第一版优先人物辨识、体型保留和换装衔接。身体参数是生成外观的约束，不提供厘米级还原、服装合身度预测、尺码推荐或布料物理模拟的承诺。沿用现有照片式实验能力及两家个人 Key 图像服务。

不包含 3D、旋转视角、实时滑杆变形、视频、训练个人模型、云端人物资料账号或自动批量付费生成。

## 资料与生成方式

同一表单提供“基于照片”和“仅用参数”两种方式。切换不主动删除草稿，但提交时只采用当前方式需要的资料；参数方式绝不夹带此前选过的本人照片。

共同字段：

- 名称，默认“我的模特”，可改名。
- 身高（cm）、体重（kg）为必填；不预填虚构身体数值。
- 胸围、腰围、臀围、肩宽、内侧腿长（cm）为可选，收在“更多身体参数”内；缺失表示未知，不填 0、不用身高体重推算三围。
- 可选补充描述，最多 200 字，用于发型、体态等生成偏好。

基于照片：至少选择一张脸部照或正面全身照，侧面照可选。最多三个有明确用途的照片槽。只有脸部照时，身体主要参考参数；没有清晰脸部的全身照无法保证五官相似，不假装能恢复遮挡细节。界面只作拍照指导，不增加人脸识别、身份验证或自动测量流程。照片可单独移除、替换和完整预览。

照片主导人物面容、肤色和发型；明确填写的身体尺寸作为目标体型约束，照片补充体态。默认不自动瘦身、拉腿或把体型改成内置模特。若输入目标尺寸与旧照片不同，说明按所填目标生成，不静默改写数值。

仅用参数：无需提供照片，生成虚拟人脸；增加可选“外观呈现”（女性／男性／中性，默认女性）与补充描述。未指定的面容由服务生成，不要求每个人都有独一无二的虚拟脸。

数值允许小数，前后端统一拒绝非有限值、零、负数和明显超出录入范围的值；具体宽容范围由实现者集中定义并测试，不用固定三围比例判断身体是否正常。

## 页面与操作流程

1. 个人页新增“我的模特”；试衣页的模特区也能进入同一管理入口。
2. “我的模特”列出已保存底图、名称、生成方式、身高体重摘要；支持查看、改名、删除、设为默认及“以此调整”。内置模特始终可选，无个人模特时保持现有试衣体验。
3. “捏模特”填写资料与选照片，明确展示当前生成服务、将发送的照片数量和可能计费；用户主动确认一次生成，才入现有后台任务队列。
4. 生成中可离页，任务中心展示真实阶段与现有息屏帮助。完成后停在“待确认”，完整 Fit 展示、可放大。
5. 预览提供“保存模特”“调整后再生成”“舍弃”，并有“保存后设为默认试衣模特”选项。默认勾选设为默认；保存和设为默认不再调用生成接口。
6. 保存后试衣页可切换内置或已保存的个人模特，缩略图与名称明确展示此次所用人物。

只把已明确保存的底图放入模特列表、用于试衣。关闭预览或返回不自动保存、不丢弃；未确认结果在任务中心保留，重启仍可查看。调整再生成保留旧预览，直到用户明确舍弃；每一次生成单独确认可能计费。

“以此调整”复制已保存模特的参数和可用原照进入新草稿，生成后保存为独立新版本（默认名称加后缀）；旧底图与历史试衣保留。第一版不引入覆盖原版本或版本树。照片方式继续以原照维持本人面容；参数方式可把原来已认可的虚拟模特图作为明确标注的“沿用虚拟面容”参考，保持调体型时的脸部连续性。新建参数模特则不带这个参考。

页面草图仅模拟操作；其中内置人物明确标为示意，不代表新功能的真实生成结果。视觉细节在现有七套皮肤组件、中文文案和无障碍约束内由实现者确定。

## 生成与试衣约束

输出沿用 1024×1536 的单张完整全身照，头脚完整，正面自然站姿，手臂与身体稍分离，普通中性背景和均匀光线。穿简单、不遮挡体型的上衣与短裤，保留自然比例，无额外配饰、文字或拼图。

使用现有内置成年模特作为构图／站姿参考；提示词明确这张模板不决定本人脸和目标体型。参数方式新建使用虚拟人脸，调整模式才沿用原已确认的虚拟面容。有照片时明确标注每张参考图的用途和优先级，避免把模板人脸、照片衣服或背景带入新底图。

只上传本次明确选择且属于当前方式的参考图、必要身体参数及补充描述；人物名称仅本地管理，不作为生图指令。Key 沿用现有本机加密管理，不进入人物资料、任务、日志或备份。提交确认展示实际服务和图片数量；切换服务后拒绝陈旧确认。

复用即梦与 GPT 官方适配器，不另接平台。模特生成输入为构图模板＋0–3张本人照片，参数调整可额外有一张明确的虚拟身份参考；只在此新操作中支持一张模板图的请求。保留现有试衣／人台的数量、文件尺寸和总量约束；不通过放松所有操作校验来绕过当前 2–9 张限制。生成前归一化图片并验证本地归属，不改原照片。

现有试衣仍为一张已选人物底图＋1–8件服饰。提示词按人物来源适配，个人照片模特不能继续称为“固定虚构人物”；人物脸、发型、体型、站姿来自本次已选底图。试衣只上传已保存底图和所选服饰，不再带上人物原始自拍、身体参数或补充描述。

## 持久化与兼容

按现有 Entity→DAO→薄 Repository→StateFlow ViewModel→Composable 分层接线。

新增 `PersonalModel`（命名可在实现计划中细化），保存 id、名称、生成方式、身体参数、外观呈现、描述、原照用途与本地路径、可选虚拟面容参考路径、已确认全身图、实际生成服务／模型及创建和修改时间。第一版每次确认保存创建一条独立记录；改名只改名称和修改时间，调整另建新记录。

图片走 `ImageFileHelper` 的 UUID 内部文件与完整解码校验。原照选入时复制到本机草稿独有目录或具有明确归属的内部文件；不依赖临时 Photo Picker URI。持久草稿在页面重建后保留，放弃草稿才清理独有文件。草稿清理不能删掉共享给已提交任务、原模型或其他实体的文件。

Room 28→29 追加个人模特表，并为 `TryOnResult` 追加人物来源、可空个人模特 id 和名称快照（旧记录默认内置模特）。现有 `TryOnResult.model` 继续表示 API 模型字符串，不改含义。历史人物 id 为信息快照，不设级联删除历史图的外键。

任务种类新增个人模特生成，结果停在待确认；确认保存与任务完成在同一个 Room 事务提交，重复点击幂等。任务需记录已保存的个人模特 id，删除任务不删除已保存模特；不能只用现有 `tryOnResultId` 冒充不同类型的结果标识。

任务请求引入明确 v2 分支：个人模特生成保存不可变输入快照、照片用途和参数；试衣保存本次选中的人物标识／名称快照及实际底图路径引用。路径保持在统一的可枚举图片引用结构中，不藏在无法备份映射的 JSON 文本。旧 v1 的严格三字段解码与固定模特语义继续兼容，不把空 garments 或新增字段直接塞入 v1。

试衣提交时在同一资料／引用边界验证并固定已选底图；不能到执行时才读“当前默认人物”。排队后改默认、改名或删除模特都不改变已经提交的人物。源路径数量与服饰数量分开校验，不能把个人底图混入现有一件服饰一张图的数组解释。已删除人物的失败任务重试先打开草稿让用户重选，不静默替换为内置人物并付费提交。

默认模特 id 存本机 DataStore；无效或已删除 id 回退内置并刷新 UI。不新增账号概念。换模特不改变服饰、订单、搭配、统计和已有结果。

## 文件引用、删除与备份

个人模特原照、已保存底图、调整参考、草稿源图、执行中任务引用及待确认结果都纳入统一引用保护。待确认个人模特任务除了输出图，还必须保留确认保存所需原照；不能沿用当前任务在成功后立即清空全部源图的规则。舍弃／删除时只清理已经没有任何引用的文件。

删除已保存个人模特需要确认，默认选择回退内置；已提交试衣继续使用快照底图，历史试衣结果完整保留，不取消别的任务。排队或执行中的人物任务仍按现有取消后等待读取退出的方式释放图片。

备份 8→9，同步 JSON、ZIP、预览、恢复和 CSV：

- 保存全部个人模特记录及其原照、底图和参考图；待确认任务包含输出与确认所需的原照，ZIP 重映射全部图片引用。
- 旧 1–8 备份缺少个人模特数组时补空；旧试衣补内置人物默认，旧 v1 任务仍可读；新格式缺表或损坏资料不静默丢弃。
- 导入校验方式／数值／图片用途／枚举／任务请求版本、底图完整性与结果归属；不把任意外部路径当作应用可删除文件。
- 正在执行／排队的恢复任务转中断，保留必要输入供用户检查；不启动付费生成。待确认任务可继续预览和明确保存。
- 默认选择属于本机偏好，不扩大原有设置备份范围；完整替换恢复后校验当前默认 id，有效则保留，无效回退内置，不自动指定导入的第一条。
- CSV 导出人物名称、方式、身体参数、外观呈现、描述和时间等可读资料；照片文件仍由 ZIP 管理，不导出密钥。

沿用备份锁、恢复屏障和引用租约，避免恢复、取消与删除相互删图。人物原照属于用户照片，跟现有服饰／穿搭图片一样存本机并纳入用户主动备份，不自动同步到新的外部服务。

## 验收与待验证范围

- JVM：两方式必填／选填和数值校验；照片用途与提示词优先级；仅参数不上传隐藏照片；提示词不要求沿用模板体型；旧 v1 和新 v2 编解码；两服务按操作验证输入数量；错误／取消不自动再请求。实际图像还原效果单独做人工评估，不用提示词断言冒充效果验证。
- 独立内存 Room／独立 AVD：28→29 迁移原数据全字段保全；确认保存幂等；默认切换与删除；排队人物快照；原照和底图引用保护；草稿重建／放弃；旧备份、新 ZIP 往返及待确认恢复；后台任务中断、取消与备份竞态。
- 真实 Compose：照片／参数切换、数值录入、照片替换移除、预览缩放、保存／舍弃、重新调整、试衣选择人物；七皮肤浅暗、小屏、大字体、键盘和唯一底部主操作可达；复用标准顶栏／Section／Card／Image，滚动登记 `ObserveSkinScroll`。
- 至少 `assembleDebug`；出正式包按既有 clean Release、签名和覆盖升级资料保全流程。这里只是设计，不宣称已实现或已验证。
- 付费效果评估需另有实际试验输入与调用额度：照片方式看人物相似度与体型、参数方式比较不同身高体重和围度、同一底图两套换装看脸与比例是否保持。未做真人实测前不以固定内置人物或草图证明“像本人”。
