# Lolita 完整衣橱与穿搭物品登记设计

日期：2026 年 10 月 18 日。状态：产品方案初稿，供用户审阅。

让假发、袜子、鞋履和裙装一样，拥有独立资料、实际收纳位置、购买记录、展示图片和搭配用途。用户从选裙子开始，可以找到能一起穿戴的物品，核对实际存放位置，再选择需要的单品生成试衣图。

用户明确提出扩大搭配物品的登记范围，涵盖假发、袜子、鞋子、房间和 AI 图，并要求先做产品设计。本文的分期、字段和交互均为产品经理提出的方案，尚未代表用户批准开发。

## 产品目标

优先解决三件事：知道自己有什么、找得到放在哪里、能够参与完整搭配。以如下场景验收：登记一顶奶茶色长卷假发、一双蕾丝袜、一双玛丽珍鞋，分别放入卧室假发架、衣帽间袜子抽屉和玄关鞋柜；从一条 JSK 出发选择这些物品，生成包含假发和鞋袜的全身试衣图。

登记应当轻量。用户只填名称和类型即可保存，详细规格、照片、品牌、价格和位置可以后补。未知品牌不应阻挡登记，未录价格不解释成免费。

本轮不设计三维房屋、商城、自动购物、强制全套穿戴或 AI 合身保证。护理耗材可作为后续扩展，不能使第一次登记假发就变成填写复杂台账。

## 现有基础与需要补齐的部分

截至当前源码，应用版本为 2.54.0，Room 为 29，备份格式为 9。

| 已有能力 | 对新需求的影响 |
| --- | --- |
| 分类仅有服装与配饰两个分组，已预设袜子 | 袜子可登记，但没有独立规格和明确试衣位置；假发、鞋履没有完整内置支持 |
| Item 统一承载品牌、分类、尺码、颜色、图片、位置、订单关联等 | 继续复用统一物品记录，避免另造互不相通的假发库、鞋库 |
| 物品有一层父子小物关系及共价规则 | 商品归属与搭配使用须分别处理，不能让共用假发绑定某条裙子 |
| Location 是平面位置，已有卧室等六张房间插图 | 需要补充柜架、抽屉层级；保留现有房间与图片 |
| 小物展示图上传单张商品图；裙类使用正面人台 | 可扩展为按品类选择展示方式，但现有小物提示词会移除 hair，不适合直接生成假发 |
| 试衣有主件、上装、下装、外搭、头饰、手饰、腰饰、其他八种角色 | 需新增假发、袜装、鞋履等角色；当前保留人物 hair 的规则与戴假发冲突 |
| 试衣选 1 至 8 件，至少一件服装，任务中心后台执行 | 首期保留容量与后台机制；完整搭配的记录容量和 AI 输入容量分开 |
| Coordinate 通过 Item.coordinateId 组织归属 | 不能直接用于同一双鞋反复加入多个独立搭配方案 |
| MatchingEngine 使用颜色、风格、季节与历史共现 | 推荐前先按穿戴位置筛候选，避免把相似颜色的裙子当作鞋袜补位 |

## 物品分类

用户看到的一级入口采用七类穿戴物品，护理收纳作为可选扩展。二级类型可搜索、自定义。不要把鞋型、袜长、发长等全部展开成首页页签。

| 一级品类 | 二级类型示例 | 登记要点 |
| --- | --- | --- |
| 服装 | JSK、OP、SK、衬衫、外套、斗篷、披肩、裙撑、打底裤 | 轮廓、尺码、季节、搭配层次 |
| 假发 | 全头假发、发片、刘海片、假马尾、假辫 | 发色、长度、卷度、组件与佩戴方式 |
| 袜装 | 短袜、中筒袜、及膝袜、过膝袜、连裤袜、袜套 | 袜长、颜色、花纹、厚度、单双情况 |
| 鞋履 | 玛丽珍鞋、茶会鞋、浅口鞋、短靴、长靴、其他鞋履 | 鞋码、鞋跟、舒适度与实穿情况 |
| 头饰与配饰 | KC、Bonnet、发带、发夹、帽子、项链、耳饰、胸针、腰饰、手袖、手套 | 具体穿戴位置、成对成组与可复用性 |
| 包袋 | 手提包、斜挎包、背包、手拿包 | 背法、容量、是否容纳手机 |
| 手持道具 | 阳伞、扇子、手杖、玩偶、花束 | 手持位置、便携性与用途 |
| 护理收纳，后续可选 | 假发支架、发网、梳子、鞋垫、收纳袋 | 不进入默认试衣和穿搭补齐 |

这些例子是初始选项，不构成穿搭标准。已有斗篷、披肩不会因显示在服装入口就自动改动购买归属或订单。

### 分类语义

将三个概念分开：

- 品类回答“它是什么”，例如假发、鞋履；名称重命名不改变语义。
- 穿戴位置回答“这次怎么用”，例如头发、头饰、袜装、脚部、手持。
- 商品归属回答“是否属于某个购买主件”，继续使用现有父子关系。

技术上在 Category 增加稳定的语义类型，保留旧 `CategoryGroup` 值供历史兼容，展示入口从新语义派生。旧记录默认未确认；只对应用可证明身份的内置分类直接补齐，用户自定义名称提供候选供确认，不依赖宽泛正则静默重分类。新建自定义类型时必须选择所属品类和默认穿戴位置；历史未知类型继续可读、可编辑。

编辑已使用分类的品类时，先显示影响的物品数量，再确认统一变更。每件物品的专属资料保留；不因从鞋履改为其他就删除原鞋码。删除分类继续要求先迁移引用物品。

### 独立物品与成对成组

假发、鞋袜和包袋默认独立登记，不默认挂到裙子下。用户明确选择“属于这件商品的配套小物”时才建立原有父子关系，计价继续由原账本控制。

一双鞋、一双袜、一对手袖、一组配套发夹，可以各是一条物品记录，并保存“单只、成双、成组、组合不明”的组成信息。单只原图不会由 AI 自动补成一双。两双同款袜子若需要分别记录位置或护理状态，复制资料创建两条记录；复制只带基本资料与规格，不复制订单、实付、导入唯一标识和待执行任务，首期不引入库存数量和拆分账本。

## 登记与详情

### 新增流程

统一“新增物品”入口，流程为选择品类、填写基本资料、按需补充专属规格、保存。用户从鞋履筛选或鞋柜内新增时，预填品类或位置，保存前可以修改。

基础区展示名称、二级类型、照片、品牌、颜色、尺码和收纳位置；类型决定专属字段。价格与付款沿用现有独立流程，不为了保存一顶无品牌假发要求先建订单。未知品牌通过明确的系统“未设置品牌”记录兼容当前非空品牌外键，和“其他品牌”“无牌产品”保持区分，不混入真实商标补图。

只要求名称和有效分类。照片可选；没有照片的记录可以参与收纳和搭配清单，调用 AI 时提示需要补参考图。公共与专属字段合计再多也不增加首次保存门槛。资料使用可恢复草稿，切换品类保留已填写的专属值，重新显示时继续可编辑。

| 品类 | 默认可见的专属项 | 展开后可补充 |
| --- | --- | --- |
| 假发 | 主要发色、长度厘米、直卷、是否含附加发片 | 刘海、分缝、材质、耐热说明、头围适配、修剪造型备注 |
| 袜装 | 袜长类型、尺码、颜色或花纹、成对情况 | 厚薄、DEN 原始标识、足长适配、材质、透肤情况 |
| 鞋履 | 尺码原文和尺码体系、颜色、跟高厘米 | 内长厘米、筒高、鞋头、扣带、脚感、适合步行时长备注 |
| 裙撑 | 长度厘米、轮廓、蓬度 | 腰围、层数、材质、与裙长搭配备注 |
| 配饰 | 穿戴位置、成对成组 | 尺寸、固定方式、金属或材质备注 |
| 包袋与道具 | 使用或携带方式 | 尺寸、容量、可折叠情况 |

原有 `size` 保留原始字符串；新增鞋码体系等解释字段不自动换算，也不将旧 XS/M 等清空。未知材质、耐热、DEN、舒适度留空，不从商品照片推定。脚感为用户自评，不由生图结果判定。

详情依次展示完整主图、名称与订单摘要、专属资料、存放位置、关联搭配和图片操作。图片继续支持放大、追加及设为封面，位置支持直接进入相应柜架查看。每个品类都要有完整的列表、详情、编辑入口。

### 找物与筛选

保持首页四个主 Tab 与底部导航布局，现有服饰页标题可保留，新增按钮统一使用“物品”。一级品类使用横向可滚动筛选，二级类型用可搜索选择器；不在顶栏塞入七个新 Tab。

按品类、类型、颜色、品牌、尺码、房间和具体收纳位置叠加筛选。假发支持长度与直卷，鞋履支持鞋码与跟高；只有当前品类显示对应字段。搜索覆盖名称、品牌、分类、颜色和位置路径，不扫描私密备注作为默认匹配项。

筛选到假发、鞋履等品类时必须显示符合条件的挂载小物，不能沿用“无搜索时只显示主件”的规则把它们隐藏。同一物品只显示一次，并标记配套归属。独立物品与挂载物品都能被穿搭、位置和 AI 选择器检索。

### 导入与统计联动

淘宝商品和订单导入沿用逐件确认，将假发、袜装、鞋履加入明确分类候选。组合商品仍按明确款式拆分，不按颜色或尺码展开；从一张整套图无法确定单件时提示核对，不能把套餐总价分别当作鞋袜价格。CSV 导入允许映射品类、规格及位置路径，位置不明时保留未设置，重复名称让用户选择，不按相似名称自动合并。

统计概况补充各品类记录数，总数按 Item id 去重，明确是否包含挂载小物，主件数与全部物品数分别标注。一双鞋为一条记录，不将一双计为两件。消费仍按原订单和共价小物规则汇总，一条购买证据不会因归入多个搭配、房间筛选或新品类重复计费；金额隐私设置继续覆盖所有新增摘要。

分享默认只包含用户本次选择的图片、名称及可选品牌，不带位置、鞋码、个人尺码、价格和备注。公共资料或共享库若需承载新规格，应另行明确可公开字段；首期新收纳路径和专属资料仅在本机及用户主动导出的备份中保存，现有同步和公共资料导入必须保留这些本机字段。

## 房间与实际收纳

### 层级与操作

延续现有卧室、衣帽间、玄关等房间。增加最多两层收纳位置，完整路径最多为“房间 → 柜架或收纳盒 → 层或格”，允许只选房间或柜架。

| 房间示例 | 柜架示例 | 具体层格示例 |
| --- | --- | --- |
| 卧室 | 假发架、梳妆台 | 上层、抽屉、棕色长卷标签 |
| 衣帽间 | 袜子抽屉、配饰收纳盒、裙撑架 | 第一格、白色袜区、头饰层 |
| 玄关 | 鞋柜、包架、伞架 | 第二层、常穿区 |
| 储物间 | 换季箱 | 秋冬箱、备用配件袋 |

“假发架”“鞋柜”是收纳位置模板，不自动冒充新房间。房间本身也允许用户按习惯命名为梳妆区等名称。

房间详情先展示下属柜架和未进一步定位的物品，点柜架可看全部后代物品。列表显示缩略图、数量、当前路径，支持搜索和批量移动。数量按物品记录计数，明确标注“条记录”；一双袜子仍是一条。统计和批量移动包括挂载小物。

一个物品有一个当前位置；更换房间时提示清除或重选原柜架，不能留下跨房间矛盾引用。移动柜架时随其迁移子位置及物品位置关系，确认前显示影响数量。禁止循环、超过层级及将柜架移动到自身后代。

删除有物品或子位置的节点时，要求先移动内容或明确选择“全部移至未设置位置”，不得连带删除物品。改名后路径立即更新；同一父位置下名称唯一，不同房间可以各有“鞋柜”。旧的房间位置保持原 id、名称、图片及关联。

### 初始引导与房间插图

新增“添加常用收纳”入口，一次可选假发架、鞋柜、袜子抽屉、配饰收纳盒，并选择所属现有房间。新安装也不假定每个人拥有独立衣帽间；仅在用户采纳时创建位置。升级不擅自增加房间、不修改用户布局、不重新补回用户删除过的模板。

四个模板各提供一张通用插图，七套皮肤以现有卡片、边框和表面色承接，首期不要求每个模板生成七张主题图。用户可改成照片、从相册选图或按需生成示意封面。封面只作为位置示意，不解析为真实库存，也不改变物品位置。

## AI 单品展示图

详情统一显示“AI 展示图”，进入后显示当前品类对应模式。已有裙装正面人台仍保留原行为，新增品类使用独立展示规则。服装中的非裙类首期维持现有准入，不顺带开放未经设计的上装人台模式。初始模式由确认的分类语义决定，用户可核对；不依据物品名称猜测后直接提交付费任务。历史未确认品类须先核对语义，自定义类型按已选语义使用对应模板。

| 目标 | 构图与保真要求 |
| --- | --- |
| 假发 | 单独完整展示发型，发梢与刘海不截断；保留发色、长度比例、卷度、渐变和分缝；可用不可见内部支撑，无真人面部和头模 |
| 发片或假马尾 | 只显示参考图中该组件，不补造成完整假发；保留夹扣和连接方式 |
| 袜装 | 单独平铺或自然立体展示，保留袜长、花纹、蕾丝、袜口与原单双组成，无人体腿脚 |
| 鞋履 | 沿用原图可见角度，保留鞋头、鞋跟、扣带、蝴蝶结和厚底比例；原图一只不补另一只，不编造鞋底和背面 |
| 头饰配饰与包袋道具 | 保留商品全部边缘和组成，移除拍摄人物与其他商品，细带、伞尖、链条不裁切 |
| 裙装 | 继续使用无杆正面人台，仅展示目标裙装 |

所有模式保留原图，生成结果先进入待确认。用户可以“添加到物品图片”，也可随后明确设为封面；默认不替换原封面。永久保存图片来源标识，不因任务删除而丢失“AI 生成”状态。原图、生成图均纳入图片引用保护及备份。

从真人穿搭照提取假发或鞋袜时，若目标被遮挡，提示选择更清楚的参考图；首期不承诺自动检测所有遮挡，也不通过提示词让模型编造不可见结构。预览提供“颜色、形状、组成数量、细节”核对提示，用户可直接舍弃。

假发提示词必须保留产品 hair，只移除非目标人物及其原生头发。不能复用当前小物提示词中不加区分地移除全部 hair 的描述。提示词按语义模板分发，类别名称作为数据标签处理。

生成器保留现有服务选择、加密密钥、任务中心、后台执行、明确付费确认和无自动重试规则。提交时固定品类、原图、模式、人物及服务快照；分类或图片变更后重新确认。密钥不进资料、日志或备份。

## AI 完整试衣

### 穿戴位置与冲突

新增明确的假发、袜装、鞋履、包袋、颈胸饰、裙撑和手持角色；保留已有主件、上装、下装、外搭、头饰、手腕、腰饰和其他角色。品类提供默认位置，用户可修正，自定义类型也必须能使用。裙撑作为裙内支撑，不误判为主裙，不要求外露；仅有裙撑不能满足至少一件基础服装的条件。

选中假发后允许替换原发型与发色，保留人物面容、年龄、体型、姿态及背景。未选择假发时保持原头发。头饰佩戴在本次选定的发型上，不能用发带代替假发。袜装与鞋履同时按各自参考图处理，长袜可以自然进入靴筒并受到裙摆遮挡，避免为了展示商品而改变裙长。

一顶全头假发、一双鞋是默认互斥位置。用户再选同位置时，先询问替换哪件，绝不静默移除；主裙与半裙、两件同层上装提示核对。发片可与全头假发、袜套可与袜子、不同位置配饰可组合，但必须明确组件角色；无法可靠描述时先提示调整选择。连裤袜默认不能与第二件基础袜装重叠，袜套单列可叠穿。

没有选择鞋时沿用模特鞋，未选袜装保留底图该区域，并在提交前说明；生成结果不能标成这些默认物品已登记或已选。至少保留一件服装的现有门槛，首期不开放仅一顶假发的人物局部试搭。

### 八件输入预算

首期继续最多八条物品参考，每条一张图，人物底图另外一张。天然一双或一组作为一条，不按左右拆成两个名额；独立物品不能通过拼图或打包成假组合绕开上限。

例如 JSK、衬衫、假发、KC、袜子、鞋、包、手袖正好八件。完整搭配方案可以超过八件；提交生成前显示“搭配共 11 件，本次试衣选 8 件”，让用户明确勾选本次生成子集。超限时不能自动去掉袜子、鞋或不显眼的配件。

试衣历史保存本次确实发送的物品和角色快照，未送出的物品不能标为已生成。不能将部分参考生成的图写成整套所有细节已还原。突破八件、局部试搭和分阶段追加生成属于后续能力，须分别评估两家服务、费用、人物稳定性与错误积累。

## 搭配方案与出门准备

### 可复用搭配方案

第二期增加独立的“搭配方案”，采用物品多对多引用。同一双鞋、同一顶假发可以同时出现在多套方案里，不移动 Item.coordinateId，也不改变父子归属和订单。现有“套装”继续保留原有归属语义；可从套装复制引用生成搭配方案，不能静默迁移原数据。

入口放在穿搭功能内，不新增底部导航。用户从一条裙子进入“围绕它搭配”，按主服装、内搭外搭、假发、头饰、袜装、鞋履、包袋、其他配饰选择，每个位置可以“不需要”。方案不要求占满所有位置，不因没戴假发就判为不完整。

保存的是计划，不是已穿记录；用户明确选择“记为今日穿搭”后才建立当天日记，保留照片、日期和原有编辑规则。愿望物品可以加入计划，但明确标注尚未拥有，实际出门准备不算已备齐，首期 AI 仍仅选择已拥有物品。

### 推荐与准备清单

推荐先按用户当前要补的穿戴位置筛选，再按颜色、风格、季节和已有共现排序，展示“同色系”“曾一起穿过”等实际理由。无资料时允许手选，不伪造百分比审美评分。锁定已选裙子和喜欢的鞋后，只替换其他空位；推荐不得迁移物品归属。

从方案生成一次出门准备清单，每行显示物品、位置路径与“已拿好”勾选。清单勾选不表示当天已穿，也不改变位置；本次全部完成不自动删除清单。用户可以跳过假发或加一项临时自带物品。

第二期增加独立的可用状态：可用、清洗中、护理中、外借。它与拥有、待付款等购买状态并存，不改变账本。默认不推荐暂不可用物品，仍可手动选并显示提醒；恢复可用由用户确认，不按时间自动推断。护理不做强制推送，提醒另行启用。

## 房间与收纳插图资产方案

首期发布四张模板插图，画幅沿用现有位置卡片，主要内容在居中安全区，小尺寸下能分辨用途。低饱和暖白背景、柔和光线、干净空间、无文字和商标，不画真人，不把空位置画成用户已拥有某件商品。区别于单品生成，模板插图属于示意素材。

| 素材 | 画面方向 | 必须避免 |
| --- | --- | --- |
| 假发架 | 简洁梳妆收纳角、可辨认的空置圆顶假发支撑架、少量空收纳盒 | 真人面部、真实品牌假发商品、密集散乱发丝 |
| 鞋柜 | 玄关矮柜、清楚的开放隔层、少量抽象鞋形作为用途提示 | 可辨商标、具体商品仿制、挤满细碎鞋子 |
| 袜子抽屉 | 俯视分格抽屉、少量整齐折叠的纯色袜形 | 文字标签、虚构库存数字 |
| 配饰收纳盒 | 打开的浅色分格盒、少量中性发夹与蝴蝶结形状 | 真人照片、过多首饰高光和伪品牌标识 |

基础生成提示词示例：“为中文 Lolita 衣橱应用绘制收纳位置示意插图，温暖细腻的绘本室内风格，柔和自然光，干净低饱和背景，主体为玄关开放式鞋柜，隔层清晰，中心构图，主体位于可裁切安全区，可有少量无品牌抽象鞋形说明用途，无文字，无数字，无标识，无真人，不表现为真实用户库存。”其余模板替换主体与视角；实际执行需逐张记录完整提示词、来源、文件 SHA256 及裁切验证。

内置素材随应用离线提供，不触发用户付费接口；自定义位置的“AI 示意封面”可排在第二期，入口清楚显示将上传的内容。默认只发送所选位置名称和用户填写的画面描述，不上传真实物品、私密备注、地址或整个房间照片。

## 数据与兼容要求

这是数据结构调整，实施时必须从当前实际 schema 升版本并补 Migration，导出新 Room schema。以下是产品所需的语义边界，具体列名、索引及资料存储方式由实施方案确定。

| 数据 | 要求 |
| --- | --- |
| Category 语义 | 稳定品类、默认穿戴角色、历史未确认状态；重命名不改变生图语义 |
| 物品专属资料 | 关联现有 Item，使用有版本的类型化字段；未知值留空，切换类型保留历史资料 |
| 收纳节点 | 关联原 Location，可选父节点；同父同名约束、层数及循环校验 |
| Item 位置 | 原 locationId 表示房间，新增可空收纳节点；事务保证房间与节点一致 |
| 图片来源 | 持久记录原图或生成图及生成模式；引用既有路径，不重复复制已有图片 |
| 搭配方案，第二期 | 独立方案和成员引用，支持角色及次序；删除物品后保留名称缩略信息并标记失效，不级联删除整套方案 |
| 可用状态，第二期 | 独立于购买状态；不影响余额、实付与付清判断 |

专属资料、收纳节点、语义、图片来源、后续搭配方案和可用状态须完整覆盖备份 JSON、ZIP、预览、恢复和适用的 CSV 列。旧备份没有的新字段默认空或未确认，不能擅自分类、补价格或移动位置。未知新枚举按当前严格兼容规则处理，不悄悄回退成错误类型。

待执行图像任务使用新版本不可变请求；旧请求和旧角色原样解码，已排队的旧任务不因为升级分类而改变付费内容。试衣历史保留原名称、角色和人物快照。生成图片及待确认结果必须继续纳入引用保护、恢复校验与删除清理。

品牌、现有图片顺序、原尺码、Item id、parentItemId、Coordinate、订单、付款阶段和实付记录保持。原有房间初始化完成标志继续有效；新模板必须由用户明确采纳，不靠重置初始化标志完成升级。

## 分期交付

| 阶段 | 交付范围 | 完成条件 |
| --- | --- | --- |
| 第一期，登记与试穿 | 七类穿戴物品、搜索型分类、专属资料、未知品牌、柜架层格、四张内置收纳图、品类展示图、假发鞋袜等试衣角色与冲突处理、八件确认、兼容备份 | 假发袜鞋可独立保存、找到、生成展示图并与裙装实际试衣 |
| 第二期，重复使用与准备 | 多对多搭配方案、按位置补齐、准备清单、护理可用状态、自定义位置 AI 示意封面 | 同一鞋袜可复用于多套方案，无归属迁移；按实际位置完成拿取 |
| 第三期，验证后扩展 | 可选护理收纳用品、局部试搭、超过八件的生成策略、重复款批量登记 | 先确认使用收益和真实生成质量，再决定是否扩容 |

第一期的登记、收纳和 AI 是完整交付范围，不将鞋袜藏在普通配饰里就视为完成。第二期前已有手动试衣可以反复选用同一物品，但不能把现有套装归属当成已支持可复用搭配方案。

## 验收场景

1. 仅填名称和“全头假发”可保存；未知品牌、无价格不阻挡，重进补充资料不丢原图和订单。
2. 登记袜子和鞋可分别录 23 至 25 cm、EU 37 等原始尺码，不将数字当成服装码或自动转换。
3. 一双袜子是一条记录，原图只显示一只时，生成规则不要求补出另一只。
4. 假发分类改名后依然使用假发规则；已有自定义模糊类型升级后不被静默当作全头假发。
5. 品类筛选、柜架列表、穿搭与试衣能找到独立及挂载小物，不因父子关系漏项或重复计数。
6. 将鞋移至“玄关 → 鞋柜 → 第二层”，重命名鞋柜后路径随之更新；删除有内容的位置必须先处理内容，物品仍在。
7. 升级及恢复后六个旧房间、用户照片和物品位置保全；删除过的默认位置不复活。
8. 假发展示图不因通用移除 hair 指令被清空；发片不补成整顶，鞋袜不补造单双和背面细节。此项需要真实图像人工评审。
9. 选假发和 KC 时提示词允许换发型且保留脸，头饰按新发型佩戴；选袜子与鞋时角色明确且裙长不为展示袜子被缩短。此项需要真实图像人工评审。
10. 同时选两双鞋时明确选择替换或返回，用户筛选和切换页面不会丢失其他已选项。
11. 八件可提交，第九件不得静默删除或拼图规避；至少一件服装的要求保持，无图物品提示补图。
12. 生成先待确认，追加图片不改变封面；设封面需明确操作，原图、来源及 ZIP 往返完整保留。
13. 旧任务、旧试衣历史和旧备份可读；升级不自动调用付费接口，中断任务不自动重发。
14. 新页面与图标覆盖七套皮肤、浅暗、小屏及大字体，长鞋码和位置路径不遮挡保存操作。
15. 第二期同一双鞋加入三套搭配均可保留；记录今日穿搭不移动套装或商品父子归属，准备勾选不冒充真实穿着。

实现验证以编译、独立 Room 与设置回归、独立 AVD 的真实 Compose 流程和旧包无损升级为主；不清理用户设备数据。文档和受控接口测试只证明规则与流程，不能替代假发、细袜花纹、鞋型及人物一致性的真实图像评审。付费评估需另行明确额度，本次设计不执行 API 调用。

## 产品经理的主要取舍

优先采用统一物品库和按类型变化的轻量表单，避免维护多个互不相通的小仓库。房间扩展到真实柜架层格，避免为假发、袜子、鞋子各造一个不符合实际的房间。商品归属沿用原规则，可重复搭配另建多对多方案。

首期保留八件生成上限，明确选择子集；不以拼图提高表面容量。首次上线以登记、找物、展示图和完整试衣为边界；护理耗材和复杂库存后置。用户可以在审阅时调整分期或字段优先级。
