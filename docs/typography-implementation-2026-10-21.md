# 字体层级统一实施记录（2.66.1）

本轮对应用户“字体没有规格设计感，请设计师统一看；现代手机是2K屏”的要求。前置方案见[设计记录](plans/2026-10-21-typography-system.md)，独立设计角色审阅原实现、七皮肤图稿和真实页面，不涉及新生图或付费请求。

## 实现

Type.kt成为七皮肤唯一规格：主卡22/30、顶栏20/28、分区18/26、条目和正文16/24、辅助13/20sp；按钮15/22，元数据与底栏12/18，字距0。标题保留各皮肤字体，阅读、输入、按钮、中英数字及金额恢复统一阅读字形。SkinConfigs不再独立复制Material默认规格。高频列表、设置管理行、顶栏、分区和统计Tab消费对应角色，不机械替换微型日历与字体演示。

首页保留四标签及搜索／筛选／排序／视图同排；Tab内容去除默认横向留白，搜索与右侧控制统一32dp，使用最小高度随系统字体增长。筛选角标按实际测量预留上方空间，保留12sp和筛选符号下半部；0/3/12在普通和两倍字体下分别检查。

统计原本把八类明细直接接在四项概况后，使消费摘要后移。先补七皮肤统计图稿，再按设计角色认可的“衣橱概况→消费／最高实付→品类概况→品牌”移动现有分区，保留完整登记摘要、分类数量和原导航。金额隐私仍整块隐藏消费和最高实付。旧2.65.0源码在临时测试宿主中仅升安装版本码，已复现旧首300dp断言失败；不把它误归为新字体引入的问题。

## 定向验证与证据边界

真实像素为1440×3200，正常density600约384dp；小屏density720约320dp、系统fontScale2.0，并使用真实IME。统计另有360dp普通、320dp两倍字体受控展示。前期已有独立AVD，发现并行任务共用后改用专用Typography Test／Release AVD；没有清理用户设备。接入并行发布2.66.0的队列功能后顺延版本为2.66.1/138。

用例按文字和布局的实际调用范围选择，最终去重结果见[验证记录](visuals/2026-10-21-typography-native/verification.json)：字体层级／七皮肤混排与首页、大字真实IME，个人／实验室／单品／批次封面入口，小屏批量选择与费用确认，尺码编辑，统计金额隐私／长金额／长品牌／原导航，以及新队列页与选择对话框的七皮肤和小屏操作。未运行无关全量JVM或数据库、图片与备份全库审计。

测试修复了两类宿主问题：LazyColumn未组合的输入需要先按列表滚动定位；超高批次卡中目标按钮需继续滚动到具体后代。文字完成度检查按真实行边界、完整字符范围和省略状态判断，避免缓存MultiParagraph的空白约束宽度引发误报；实际大字首页横向裁字则通过取消默认Tab留白修正，没有缩小字体或放宽断言。
