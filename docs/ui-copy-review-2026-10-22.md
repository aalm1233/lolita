# Lolita 全界面文字审视

2026 年 10 月 22 日。审视基线为 2.66.2，源码 `c42146eb`。

目前最需要处理的是三类文字：与实际行为不一致的描述、同一页反复出现的解释、把内部实现用语直接交给用户的提示。日常页面可以更轻，AI 页面应把图片和当前操作放在前面，账本页面则需要保留准确的金额口径和异常状态。

本次交付为逐页删改建议，未改动应用文案或行为。43 个导航定义及其主页页签、统计子页、识图工作页和共用弹窗已按源码逐项核对；视觉判断结合项目已有原生截图与本次独立测试 AVD 的页面。下文分别标明证据，不将源码审视写成每个状态均已实机验证。

后续实施见[全界面文案优化记录](ui-copy-implementation-2026-10-22.md)，下文保留原审视基线与建议。

## 优先修正文案含义

这些问题会影响用户理解，应先于一般精简处理。

| 编号 | 页面及原文 | 问题 | 建议 |
| --- | --- | --- | --- |
| A01 | 备份页 JSON：「包含所有数据，可用于完整备份和恢复」 | JSON 不含图片，容易让用户以为已经完整保全照片。 | 标题改「数据备份（JSON，不含图片）」；说明改「仅备份记录；完整保存记录和图片请选择 ZIP」。ZIP 标注「完整备份，推荐」。 |
| A02 | 个人页备份入口：「支持 JSON 和 CSV 格式」 | 漏写推荐的 ZIP，且 CSV 只能导出查看，不能用于完整恢复。 | 改「使用 ZIP 备份记录和图片」。具体格式能力放在备份页分别说明。 |

| A04 | 物品编辑及小物说明：「收货状态」「收货状态按本件付款计算」 | 系统依据付款更新拥有状态，并没有记录物流是否收货。 | 字段改「拥有状态」；解释改「根据付款情况更新，付清后为已拥有」。小物说明同步，不改变现有付款规则。 |
| A05 | 心愿统计：「已实现」 | 数值使用全部已拥有数 ÷（已拥有数＋心愿数），没有证明这些物品曾经是心愿。 | 在保留现有计算的前提下改「已拥有占比」，说明分母为已拥有与心愿合计。若以后要做真正的心愿达成率，应另行设计历史记录。 |
| A06 | 心愿统计：「愿望单预算」 | 金额来自已录参考价格的合计，并不是用户设置的支出上限；还会排除未录价、多个候选价格及共价小物。 | 改「心愿参考总价」。口径说明「仅合计有唯一价格的独立计价心愿物品」。不能把缺少价格解释为免费。 |

| A08 | 任务中心：「物品详情的人台图、小物展示图」 | 当前普通入口已统一成「生成展示图」；总说明又只提人台图和个人模特需确认。 | 空态改「从展示图、虚拟试衣或我的模特提交后，可在这里查看」。状态说明按任务类型区分，不能暗示试衣历史也必须手动保存。 |
| A09 | 试衣失效提示：「服饰已不在已拥有衣橱」 | 试衣也支持心愿物品，错误提示与准入范围冲突。 | 改「该物品已不可用于试衣，请移除后重新选择」。具体原因已知时直接说明已删除或状态已变化。 |
| A10 | 通用弹窗：「确认返回」／按钮「返回」 | 没有在按钮中交代未保存修改会丢失。 | 对会丢失修改的流程使用「放弃未保存的修改？」＋「放弃并返回／继续编辑」。保留草稿的流程单独使用「保留草稿并返回」，不能套同一文案。 |
| A11 | 房间卡片：「暂无物品」 | 代码按缩略图列表是否为空显示；有物品但都没照片时，也可能显示没有物品。 | 只有记录数为 0 才表达空房间；有记录无照片时省去图片空态，或写「暂无照片」。 |
| A12 | 模特照片引导：「两种都有，更像你」；实验室假发入口：「保留发型与发梢」 | 容易读成效果保证，而生成结果仍需核对。 | 前者改「可同时提供脸部照与正面全身照」；后者改「选择假发与头模，生成佩戴预览」。 |

| 批次任务卡 | 总数、确认数、失败数之后又有一整句处理流程。 | 保留数字摘要，删除每张卡都重复的「主视图、透明层与确认素材集中处理…」；「打开本批任务流」改「查看批次」。 |

| 停止后续排队与批量舍弃 | 两种操作边界清楚，应保留。 | 「停止后续 N 个排队任务」可缩为「停止后续排队（N）」；确认页保留当前执行继续、状态变化跳过、只舍弃未保存结果的区别，不能统一成含糊的「取消全部」。 |

| 图片裁切 | 分辨率、降采样、EXIF、实际像素等说明占用编辑空间。 | 默认一句「拖动调整范围，双指缩放」及「原图保留」；技术信息收入现有「图片信息」。确有降采样时用「大图已适当缩小」并保留最终尺寸可查，不让信息遮住图。 |

| 分享预览 | 隐私摘要有用，保留一处即可。 | 「仅分享照片、名称及可选品牌，不含金额等私人资料」。品牌开关保留。隐私白名单本身不因精简改变。 |
