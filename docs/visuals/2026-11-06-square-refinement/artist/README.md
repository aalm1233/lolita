# 2026-11-06 广场与物品详情艺术图稿

本目录是实现前艺术设计与本地交互原型。不是 Android 实拍、不是对真实库存的新增登记。全部读取本地首包，不访问淘宝，不上传图片，不调用付费服务。

- `index.html`：可切换图板、七皮肤浅暗，并交互浏览商品、选择具体部件、分别登记/自由组合、分部件与角色选择图片、查看登记预览。
- `flow.png`：广场→商品→自主拆分→图片归属→登记预览→衣橱物品详情，共6页。
- `light.png`、`dark.png`：七皮肤×广场/物品详情，分别14个实际效果稿。
- `large.png`：320dp、2倍字，五个关键页面。字号按比例增长，操作文案适当缩短，内容滚动，底部按钮随文本自然增高。
- `*-390.png`：独立390dp页面，便于与原生截图对照。
- `review.json`：本地HTML验证，明确不是Compose验收。HTTP/HTTPS请求全部阻断。
- `asset-sources.json`：每张预览的首包内路径、原始SHA、商品与角色。预览压缩不改首包原件。

## 对实拍问题的处理

实拍的标题、搜索、两行Chip、附加筛选说明叠加通栏240dp照片，让第一个商品标题落到首屏下沿。本方案保留必要筛选，去掉重复的大页面标题，搜索44dp、动态Tab44dp、店铺与属性筛选同一行；首卡图片180dp完整Fit，标题、购买内容、时间及明确款式报价与图片同屏。模特整搭只表达系列，进入商品后优先展示明确JSK、KC、内搭的独立图，不能将整搭当成所选单件的实物图。

物品详情采用标准顶栏，完整主图238dp左右（实际实现可按视口收敛到180—260dp），其后为品牌、名称、类型/颜色/尺码和拥有状态，立即呈现当前购买摘要。图稿是无订单心愿态，故显示“尚未记录购买”，不能展示虚构余额；已有订单继续呈现当前订单/实付/待付和原管理入口。资料用现有LolitaSection，尺寸、材质、备注、来源依层次展开，保留用户资料，避免JSON、内部标识和采集版本堆满首屏。编辑与删除、关联小物、设为封面等原能力均保留，只调整层次。

## 拆分与选图规则

1. 先选实际完整SKU，再勾选该SKU实际包含的部件。图稿用浅蓝JSK+KC，内搭未包含所以不可直接勾选。部件缺失/非独立销售要保留明确状态，不按模特照片推断包含。
2. 用户可分别登记，也可合成一组，主动确认名称、类型与组成；小物组合与衣橱套装、主件小物关系分开，不自动挂入旧套装。
3. 每个输出物品拥有独立的主图、规格图、尺码资料选择。切换部件或资料角色保留已选值；可放大原图再分配。图稿对JSK默认只选JSK正面，KC默认只选KC，不默认给每件复制模特整搭封面。
4. 所有原图与来源保全在公开目录；登记只独立复制用户选中的图片，已保存/草稿图片不依赖公开目录生命周期。未挑图片不能默默用整搭顶替，可以明确保留无图并后补。
5. 尺码资料必须按具体部件确认。JSK的M不传给KC，组合价不复制成每件参考价；赠品默认不选，不自动录价、订单、实付或已拥有。
6. 首版沿用逐件编辑和稳定去重标识，不以多件预览冒充原子多件保存；明确已保存/未保存数量与继续登记入口。原子事务是否实施由实际实现记录说明。

## 皮肤、兼容与验收边界

七套图稿使用项目已有背景预览、颜色方向与形状：甜美曲线、哥特切角、中华舒展、古典对称、海军厚画框、田园虚线、维多利亚双层分区边框。原生必须消费现有皮肤令牌和真实provider；本HTML不要求新增全局色值或改其他页面。

本轮图片选择数据需兼容已有v1包，缺少精确映射时用户手动选择原图而不猜对应部件。只改变输出草稿的选图与结构，不改旧衣橱记录；是否增加schema/备份字段由主实现根据最终存储方案决定并记录。图稿不含云同步、登录或购买操作，不扩大费用和隐私边界。

原生验收应对照本稿，覆盖首包三店、至少JSK/KC/内搭与Neo独立“套装”维度、自由多选分件、组合名称/组成、每件独立封面与资料、未知规格、全图放大、尾款只读、返回草稿及重复提交，七皮肤浅暗、320dp两倍字和真实键盘。HTML图板检查不能替代这些验收。
