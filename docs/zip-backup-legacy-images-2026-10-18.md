# 旧商品图片导致 ZIP 备份失败

用户截图 `1000033962.jpg` 显示：“备份失败：收纳、草稿或识图证据图片缺失、损坏或不属于本机图片目录”。截图仅作问题定位，不将私人截图复制进仓库。

## 已核对的问题与实施方案

`BackupManager.snapshot` 在导出前调用 `validateWardrobeImages`。这处校验对全部草稿图片和 v4 展示任务输入使用个人照片的 UUID 文件名规则，存在两处与生产流程不一致的兼容缺口：

- 编辑与复制草稿沿用原物品相册、尺码图的路径。完整、可读且位于本机 `files/images` 的旧文件名也会被拒绝。
- 展示图任务准入已经允许旧商品图片，备份却再次用 UUID 规则拒绝。JSON 恢复的资源可用性检查同样会把这些有效历史输入误标为缺失。

实施顺序：先通过真实 Room、商品复制草稿及展示任务准入复现失败；再按角色修复导出和恢复的相同校验；最后验证 JSON/ZIP 往返、反例及正式同签名升级并发布。

草稿相册和尺码图允许历史文件名，继续检查精确私有路径、非软链接、完整性、尺寸和解码。证据、识图选区、收纳新图和个人照片保持现有严格规则。v4 展示任务只对冻结原图及未经裁切的商品输入使用商品校验；派生选区、模板和其他任务输入保持 UUID 规则。任务校验不依赖当前物品仍存在或仍引用该图，保全历史冻结请求。

本轮属于后台兼容修复，没有新增页面、操作或图片展示位置，沿用现有七皮肤界面，无需新界面图。原图不重命名、不重编码，不改相册顺序、封面或草稿。ZIP 继续使用独立 UUID 归档名及 SHA256 清单，恢复在独立文件中重映射路径。缺失、损坏或越界文件仍明确失败，不以跳过图片宣称完整备份。

Room30、备份格式10保持不变，无数据迁移或启动刷新。原订单、实付、来源和修改时间保持；本轮不涉及金额展示、云同步或付费请求。
