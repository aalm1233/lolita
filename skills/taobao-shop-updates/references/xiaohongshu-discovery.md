# 小红书官方预热巡检

现有广场店铺名册是巡检范围。用小红书提前发现官方图透、预约和销售计划，再用淘宝商品页确认实际可购阶段、链接、报价和库存。首次收录和更新都保留两边各自的来源和观察时间。

## 按店巡检

1. 读取 `~/Downloads/taobao-shop-updates/catalog-state/social/xiaohongshu/accounts.json` 中与广场稳定 shopId 对应的公开主页。名册中的店铺即使缺少账号映射也继续做淘宝采集。缺失的映射可用站内用户搜索补查。用认证主体、官方跨平台链接，或主页公开简介、店铺名和多条独家新品公告交叉确认。仅有同名或转载证据时记录为 `unverified`，写明原因。
2. 复用已授权的本机浏览器正常查看公开笔记。可先用浏览器连接，必要时通过正常桌面浏览器记录公开页面。遇登录、验证码、权限或限流时记录当前店铺和原因，继续原淘宝流程。仅浏览官方公开发布，评论、买家图和用户账号信息不进入采集。
3. 巡检近期笔记和与待跟进批次有关的置顶笔记。区分笔记发布时间、活动期、预约或开售期、尾款截止与发货时间。品牌设计图、图透或走秀可作身份线索；明确计划时间、活动安排、发售说明或正式口径才可作为销售意图证据。
4. 每轮在该店输出目录写 `social/xiaohongshu/discovery.json`，记录 `shopId`、主页、实际检查时间、状态（`checked` / `unverified` / `blocked`）、以及读到的相关笔记。笔记只保留公开发布者、无会话参数的主页及笔记链接、笔记ID、公布的字段、原文定位和本地证据文件。官方网页可下载的图保留下载件与SHA；有平台水印或只有截图时明确标记。避免记录登录参数、买家信息和评论。
5. 把已确认销售计划但缺少可对应淘宝商品或完整公开服饰选项的批次写入 `~/Downloads/taobao-shop-updates/catalog-state/social/xiaohongshu/previews.json` 的 `previews`，保存店铺、系列、计划日期、来源笔记、首次见到时间和具体缺项，状态为 `pending`。同一店的多个笔记围绕同系列同批次时合并来源，沿用第一次建立的记录；重复观察只更新检查时间。后续找齐淘宝对应关系后记为 `matched`，附真实商品ID、广场动态ID和发布回执。若商家明确取消或已结束，也保留原记录和依据。登记用同目录的 `state_lock` 与 `atomic_json`，保留其他店铺记录。

## 并入广场

- 用店铺归属、系列名、预约区间、官方款式图或明文互链确定同一批次；同名的不同批次和不同店铺分别保留。把已确认预热线索附进该店本轮上下文，交给 dsh 在淘宝侧核实匹配；主助手照常不访问淘宝页面。
- 当对应商品已满足 v1 的公开资料契约时，使用既有设计、批次、商品、动态及SKU标识。小红书可以给「上新／预热」补预约期、造型说明、已公布的尺码表和价格预告。只发布小红书内容支持的具体字段。已有正式淘宝阶段或售价与预告不同，保留各自时间与语义，当前购买状态以商品页为准。
- 复采同批次时从既有记录和证据档案保留仍有效的预约价和部件资料，直到商家明确修订或有更新的同字段证据。小红书一时不可访问、旧笔记未在首页出现或淘宝资料缺项时沿用已核验字段，保留原观察时间。
- 将官方图上标为「预约价」的金额放入动态的 `price`，标明来源和价格口径。只有正式的逐SKU报价才写 `sku.price`。不要把活动券、预约赠品、预约价、定金和尾款混用。未确认金额继续留空。
- 尺码表绑定相应部件，原图或官方页面下载件只作为本地证据也可用于核验结构化字段。保留来源笔记链接；平台下载件或截图不能冒充淘宝主图或精确单品原图。通过 `workflow.py verify/package`、SQLite入库、只读API和实际Kotlin契约后才确认已发布。
- 官方已确认的新计划可在当轮结果中提示，即使暂缺发布条件。账号未确认、读取失败和仅有预热线索分别记录；避免将这些状态当作无预告或下架。日常没有实质变化时不重复提示同一笔记。
